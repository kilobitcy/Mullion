下面按分组列出一份比较完整的清单，标了 **[必填]**、**[常用]**、**[进阶]**，你可以按此决定“基础/高级”两级 Tab 的划分。

## 1. 会话标识与组织
- 会话名称 **[必填]**
- 所属文件夹 / 分组（树形路径）**[常用]**
- **图标**：内置图标库（Linux/Ubuntu/CentOS/Debian/Windows/Docker/K8s/路由器/数据库…）、emoji、自定义上传、或按主机名自动匹配发行版 logo
  - 未设图标时的**回落表现**：会话名首字母色块 / 按协议给默认图标 / 留空 **[常用]**
  - **状态徽标叠加**：连接中 / 已连接 / 断开 / 出错 的小角标，与基础图标的合成规则 **[常用]**
  - **尺寸与 DPI**：会话列表 / 标签页 / 终端顶部色条三处尺寸不同；高 DPI 下的资源形态（矢量 vs 多尺寸位图）**[进阶]**
  - **自定义图片的约束**：可接受格式、尺寸上限、**引用路径失效时画什么** **[进阶]**
  - **图标选择器**：内置库上百枚图标要能搜索、按类别浏览 **[常用]**
- **颜色**：标签色（hex）+ 作用范围（标签页、会话树条目、终端顶部色条、窗口边框、状态栏、滚动条、文件侧栏、任务栏图标叠加）
  - **着色强度**：整行背景填充 / 仅左侧色条 / 仅文字着色——同一作用范围下这是三种完全不同的观感 **[常用]**
  - **色阶**：每个语义色至少需「常规 / 弱化」两级，分别用于填充与边框 **[进阶]**
- **批量赋值**：选中多条会话统一改图标 / 颜色 / 分组 / 标签 **[常用]**
- 标签 tags（可多选，用于筛选）**[常用]**
- 备注 / 描述
- 是否收藏、排序权重
- 快捷别名（供快速连接命令行使用）**[进阶]**
- 是否继承父文件夹配置（哪些字段继承、哪些覆盖）**[进阶，但建议早定]**

## 2. 连接
- 协议：SSH / SFTP / Telnet / Rlogin / Serial / 本地 Shell **[必填]**
- 主机地址（IP / 域名）**[必填]**
- 端口（默认 22）**[必填]**
- IP 协议族偏好：自动 / IPv4 / IPv6
- 连接超时（秒）
- 自动重连：开关、重试间隔、最大次数 **[常用]**
- Keepalive：发送间隔、TCP keepalive 开关
- 禁用 Nagle 算法（低延迟）**[进阶]**
- 启动时自动连接 / 随工作区恢复 **[常用]**

## 3. 身份验证
- 用户名 **[必填]**
- 认证方式（可多选、可排序）：密码 / 公钥 / 键盘交互 / GSSAPI-Kerberos / PKCS#11 智能卡 **[必填]**
- 密码（存入系统钥匙串或主密码加密，不明文落盘）
- 私钥来源：文件路径 / 内置密钥库 / ssh-agent / Pageant / 1Password·系统 agent **[常用]**
- 私钥口令（passphrase）、是否记住
- Agent 转发（ForwardAgent）**[进阶]**
- 二次验证：OTP/TOTP 自动填充、验证码提示匹配规则 **[进阶]**
- 登录提示自动应答（expect / send 列表，用于交互式登录）**[进阶]**
- 主机密钥策略：严格校验 / 首次接受 / 忽略；known_hosts 文件路径 **[常用]**

## 4. 跳板机与代理
- ProxyJump 跳板链（可多级，引用已有会话或独立填写）**[常用]**
- 或自定义 ProxyCommand **[进阶]**
- 网络代理：类型（HTTP / HTTPS / SOCKS4 / SOCKS5 / 系统代理）、主机、端口、认证账号密码

## 5. 隧道 / 端口转发
- 本地转发（Local，-L）：本地地址:端口 → 目标地址:端口，列表
- 远程转发（Remote，-R）
- 动态转发 / SOCKS 代理（Dynamic，-D）
- X11 转发：开关、DISPLAY、MIT-MAGIC-COOKIE
- 每条规则的启用开关、备注、连接时自动建立 **[常用]**

## 6. SSH 协议参数 [多为进阶]
- 协议版本、密钥交换算法（KEX）优先级
- 对称加密算法（Ciphers）列表与顺序
- MAC 算法列表
- 主机密钥算法列表
- 压缩开关与级别
- 客户端标识字符串（Client version banner）伪装
- 允许的 SSH 扩展 / send env 环境变量（如 LANG、TERM 之外的自定义 env）

## 7. 终端
- 终端类型 TERM：xterm-256color / xterm / vt100 / linux / ansi **[常用]**
- 字符编码：UTF-8 / GBK / GB18030 / Big5 / EUC-JP / Latin-1，及是否自动探测 **[常用]**
- Backspace 发送：BS(^H) / DEL(^?)
- Delete 键、Home/End 键序列风格
- 回车发送：CR / CR+LF
- 本地回显、行模式（Telnet 场景）
- 自动换行、反向换行
- 滚动缓冲区行数（scrollback）**[常用]**
- 光标形状（块/竖线/下划线）、是否闪烁
- 铃声：静音 / 系统提示音 / 视觉闪烁
- 鼠标：选中即复制、右键行为（粘贴/菜单）、支持鼠标上报（应用内 vim/htop）
- 功能键映射方案、Alt 作为 Meta、AltGr 处理 **[进阶]**
- 空闲自动断开时长；空闲时发送保活字符 **[进阶]**

## 8. 外观
- 初始窗口尺寸（列 × 行）或自适应
- 字体族、字号、行高、字间距、连字（ligatures）
- 粗体处理：使用亮色 / 使用粗体字重
- 配色方案（引用全局主题或会话独立覆盖）**[常用]**
- 前景色、背景色、光标色、选中区颜色（覆盖项）
- 背景透明度、模糊
- 背景图片：路径、平铺方式、透明度 **[进阶]**
- 深/浅色模式下的颜色映射（若你的 icon/color 要跟随系统主题，这项必须有）

## 9. 日志与录制
- 自动记录会话日志：开关
- 日志目录与文件名模板（支持 `%HOST% %DATE% %TIME% %SESSION%` 变量）
- 追加 / 覆盖 / 按日期切分
- 是否记录时间戳、是否剥离 ANSI 转义序列
- 敏感信息脱敏规则 **[进阶]**
- 会话录制（asciinema 式回放）**[进阶]**

## 10. 文件传输 / SFTP
- 默认本地目录、默认远端目录
- 目录初始化命令（cd 到某路径）
- ZMODEM/XMODEM 支持与自动接收
- 传输模式：ASCII / 二进制 / 自动；同名文件冲突策略（覆盖/跳过/重命名/询问）
- 保留权限与修改时间、并发连接数 **[进阶]**

## 11. 登录后自动化
- 登录后自动执行的命令列表（逐行发送，可设延时）**[常用]**
- 登录脚本文件（Shell/JS 脚本引擎）**[进阶]**
- 初始工作目录
- 自动附加到 tmux / screen 会话（会话名、是否新建）**[实用，很多人需要]**
- 环境变量注入

## 12. 安全与防误操作
- 环境等级标记：开发 / 测试 / 预发 / 生产 —— 这项和你的颜色方案天然搭配（生产=红）**[强烈建议]**
- 执行危险命令二次确认（`rm -rf`、`shutdown`、`reboot` 关键词列表）
- 只读模式（禁止输入）
- 连接前确认弹窗
- 是否允许被“多会话广播/同步输入”包含 **[常用]**
- 是否允许写入剪贴板 / 多行粘贴前确认

## 13. Serial 专用（若支持串口）
波特率、数据位、停止位、校验位、流控（None/XON-XOFF/RTS-CTS）、串口设备号。

# 第二部分：单条会话之外

上面 §1~§13 的共同前提是「**一条**会话有哪些持久化字段」。下面三节是与之并列的另外
三个维度，它们同样属于「会话管理」，但都不能塞进上面的分组里：§A 是对会话**集合**
的操作，§B 根本不是配置（不进配置文件），§C 会引入一个新实体。

## §A 会话集合与生命周期

- **新建入口**：从零新建 / 从模板新建 / **克隆（另存为）已有会话** **[常用]**
- **快速连接**：不保存的一次性会话——直接输入 `user@host` 就连、或粘贴连接串自动解析。
  连完是否留痕（进「最近」但不进会话库）需明确 **[常用]**
- **导入**：`~/.ssh/config`、其它客户端的导出文件（PuTTY / Xshell / MobaXterm / Termius）、CSV **[常用]**
- **导出**：全部 / 仅选中；**是否包含凭据**；导出格式与可再导入性
- **备份与恢复**：自动备份的触发时机与保留份数、恢复到某个备份点
- **跨机使用**：配置目录被外部同步工具（Syncthing / Git / 网盘）接管时的要求——
  原子写、路径中不含机器绑定信息、外部改动后能重读、冲突时**报错而非静默合并**；
  凭据能否跨机解开取决于密钥来源，见 §C **[进阶]**
- **重复检测**：新建时发现同 `host:port` + 用户名的已有会话，提示而非静默建两条
- **批量编辑**：选中多条统一改分组 / 代理 / 标签 / 凭据 / 图标颜色 **[常用]**
- **删除语义**：删会话、删分组（是否级联删其下会话）、**被引用的对象**（当跳板用的会话、
  被引用的凭据）能否删——这三条必须各自明确 **[常用]**
- **排序与视图**：手动排序权重 / 按名称 / 按主机 / 按最近使用；列表 vs 树 vs 网格
- **使用统计**：最后连接时间、连接次数、累计时长、最近使用列表 **[常用]**
- **搜索**：匹配范围（名称 / 主机 / 用户名 / 标签 / 备注）、模糊匹配、
  按标签与环境等级过滤、是否支持 `tag:prod host:10.` 这类前缀语法 **[常用]**
- **键盘可达**：快速切换器（唤起后输入即筛选、回车即连），不必先打开会话管理器 **[常用]**

## §B 运行时状态展示

> **这一节不是会话字段，不进配置文件。** 它描述的是「会话管理界面上应当显示哪些
> 运行时信息」。放进来是因为它和 §1 的图标 / 颜色共用同一块界面（列表条目、标签页、
> 状态栏），设计时必须一起考虑；但它的数据来源是活的连接，不是磁盘上的记录。

- **连接状态**：未连接 / 连接中 / 已连接 / 重连中 / 失败，以及它在会话列表条目、
  标签页、图标角标三处的呈现方式 **[常用]**
- **链路延迟 RTT**：测法（**协议层往返** vs ICMP ping——代理链路下 ICMP 常被整段阻断，
  测出的数也不是实际路径）、采样间隔、展示位置 **[常用]**
- **上次连接结果**：时间 + 成功/失败 + **可操作的失败原因分类**（DNS / 拒绝 / 认证 / 主机密钥变更）
- **远端系统概况**：负载、内存、磁盘、在线用户数。关键在**取数方式**——
  独立的执行通道 vs 复用用户的交互式会话（后者会把命令打进用户正在看的界面）、
  轮询间隔、默认开关 **[进阶]**
- **传输态**：当前上传 / 下载速率、队列长度（有文件传输功能时）
- **会话时长与空闲时长**
- **边界（必须先答）**：**只显示当前值，还是保留历史曲线？**
  这一条决定了它是「状态指示」还是「监控面板」——后者是另一个产品。

## §C 身份与凭据复用

§3「身份验证」的隐含前提是「每条会话各自持有一份用户名 + 密钥」。机器上了规模
（一把密钥二十台机器）之后，这个前提就成了主要痛点：换一次密钥要改二十处。

- **凭据作为独立实体**：一份凭据（用户名 + 认证方式 + 口令 / 私钥 + passphrase）
  被多条会话引用，改一处即全部生效 **[常用]**
- **引用方式**：会话内联 vs 引用凭据库——**二选一**（任何时刻只有一个真值），
  还是「引用 + 可局部覆盖」（会产生「这条会话到底用哪个用户名」的二义状态）**[进阶，但必须早定]**
- **引用完整性**：被引用的凭据能否删除（拒绝 / 级联解绑物化 / 允许悬空）；
  悬空引用在连接时是**报错**还是回落到别的身份——**回落是安全问题**，
  用错误的身份连上生产机比连不上严重得多 **[常用]**
- **继承**：分组能否持有默认凭据。若能，改一次分组凭据就**静默切换了整组会话的登录身份**，
  须权衡；折中做法是把它降格为「新建会话时的预填默认值」，创建时物化、之后不联动 **[进阶]**
- **提取与去重**：扫描出重复的 `(用户名, 私钥)` 组合并提示提取为共享凭据。
  这应当是用户点头后的**显式动作**，而不是在格式升级时静默合并——静默合并会让用户
  在某天想给其中一台单独换密钥时，先经历一次「改一处、五台全变」**[常用]**
- **凭据的加密与密钥来源**：随机密钥存 OS 钥匙串（**机器绑定**，配置换台机器就解不开）
  vs 由主密码经 KDF 派生（可跨机）。这一条直接决定 §A 的「跨机使用」能做到哪一档 **[进阶]**
- **主密码**：是否强制、KDF 与参数、**盐随密文存放还是随机器存放**
  （随机器存 = 跨机照样解不开，等于白做）、忘记之后的后果与提示 **[进阶]**
- **密钥库**：内置管理的私钥集合 vs 只记录文件路径；**私钥文件被移动 / 删除后的表现** **[常用]**
- **外部 agent 作为一种凭据来源**：ssh-agent / Pageant / 1Password 等，与上面两种并列

## 关于 icon 与 color 的字段设计建议

```
icon:  { type: "builtin" | "emoji" | "custom", value: "ubuntu" | "🐧" | "/path/a.png" }
color: { value: "#E5484D", applyTo: ["tab", "treeItem", "topBar", "border"],
         lightVariant: "#C62828", darkVariant: "#F16A6A" }
```

三个容易被忽略的点：

1. **颜色语义化优于自由取色**。建议预设 6–8 个带含义的色板（生产/预发/测试/开发/自定义），既保证深浅主题下的对比度，也让团队内颜色含义一致。允许自由 hex，但默认走色板。
2. **继承机制**。图标和颜色最好能从文件夹继承（例如「生产环境」文件夹下所有会话默认红色），字段用「继承 / 覆盖」三态而非简单布尔。
3. **自动推断**。首次连接后读取 `/etc/os-release` 或 SSH banner，自动建议对应发行版图标，比让用户手选体验好很多。

## icon 与 color 的进一步设计建议

### 多来源优先级：继承链之外还有「自动推断」

上一节讲了「继承 / 覆盖」，但真实取值来源不止两处。至少有四层：
**会话显式设置 → 环境等级的隐含默认 → 文件夹继承 → 内置默认**。
`icon` 还多一个来源——上一节第 3 点的「自动推断」。

关键在于**自动推断不应该进这条解析链**，只应产出一条「建议」等用户点头。
否则会出现「我什么都没改，连了一次机器颜色自己变了」——而颜色一旦会自己变，
它作为「这台有多危险」的警示作用就没了。

推论：环境等级（生产 / 预发 / 测试 / 开发）作为隐含默认色**可以**进解析链，
因为它是用户显式打的标记，不是探测结果。

### 可访问性：颜色不能是唯一的区分手段

语义色板（生产=红…）必须满足两条，否则它保护不了它想保护的人：

1. **在色觉缺陷下可辨**。红/绿是最常见的一对混淆，而「生产」和「开发」用红绿区分
   恰好是最直觉的选法——直觉在这里是错的。
2. **颜色之外必须有第二个通道**。生产环境要同时有色 **和** 文字/图标标记。
   只靠颜色的方案，在色觉缺陷、屏幕色偏、投影仪、截图转灰度这四种情况下同时失效。

配套约束：前景/背景对比度要卡阈值，且「常规 / 弱化」两级色阶都要各自达标——
弱化色阶通常是最先掉下去的那个。

### 图标与颜色应当正交，不要联动

一个诱人但错误的想法：选了 Ubuntu 图标就自动配橙色。

不要这么做。**图标回答「这是什么机器」，颜色回答「这有多危险」**，两个正交维度。
一联动，颜色就被发行版占满了——满屏橙色之后，你给生产机涂的那个红色淹没在里面，
警示归零。

同理，颜色的取值应当优先绑定**环境等级**而非任何技术属性。技术属性（发行版、
是容器还是物理机、机房位置）都该走图标或标签，不该抢颜色这个稀缺通道。
