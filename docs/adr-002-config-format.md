# ADR-002: 配置文件格式 —— TOML

- 状态: 已接受
- 日期: 2026-07-23
- 关联: spec.md Q2、F70、F71、N-G4

## 背景

主机配置需要本地存储(F70 加密敏感字段、F71 可选主密码)。
主用户是个人开发者,主机规模在「几台到几十台」量级,
且非目标 N-G4 明确「配置就是本地文件,无云同步、无账号体系」。

## 决策

配置用 **TOML**。敏感字段单独加密后以密文形式存储。

## 备选与否决理由

**SQLite**。适合大量主机、复杂查询、事务,但:

- 该主机规模根本用不上这些优势(YAGNI)。
- 二进制格式不可 git diff、不可手改,且需要维护 schema 迁移。

故否掉。

## 后果 / 权衡

- **格式与加密正交**:主机名 / 端口 / 用户等非敏感字段用明文 TOML;
  密码 / 私钥口令用 Argon2id 派生密钥 + ChaCha20-Poly1305 加密成 blob
  (嵌入 TOML 或单独一个加密文件)。F70 验收「磁盘字节里搜不到明文口令」照样满足。
- TOML 可手改、可 git 版本管理、可 diff,贴合项目「可测、可复现、无黑箱」的气质。
- 几十条主机全量载入内存无压力。

## 重新考虑的触发条件

出现「管理数百台以上主机 + 需要快速检索 / 事务」的真实需求时,再评估 SQLite。
