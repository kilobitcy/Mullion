# F199–F204 SFTP / 编辑器交互六修 —— 设计

日期：2026-08-31
起因：用户在 v0.1.84 实机上提的六条优化，逐条 grilling 后定案
交付：v0.1.85

---

## 1. 六条实报与它们的真根因

用户报的是六条，但**其中三条是同一个根因**。这一节先把它们归并，否则会写出
三份互不相干的修法。

| 实报 | 编号 | 真根因 |
|---|---|---|
| SFTP 里按 F2 改名没反应 | F200 | 键根本没路由到面板 |
| 文件面板按 F5 不刷新 | （无新编号） | 同上 |
| 按 Del 想删除没反应 | F202 | 同上 |
| 路径条进编辑态要默认全选 | F201 | 独立 |
| 弹窗淹没在 pane 的黑背景里 | F203 | 独立 |
| 编辑器窗口要居中 / □ / ✕ / Ctrl+S | F204 | 独立 |

`handle_panel_key` 里 **F5 / F2 / Delete 三个分支从 D1 切片起就写好了**，一直是
死代码：键只在 `App::focus == Focus::FilesPanel` 时才路由到面板，而在 v0.1.84
之前 **`focus` 只有 F6 改得动**。用户开着侧栏、用鼠标点了一个远端文件（这在他
看来就是「选中了」）、按 F5——那个 F5 一路当普通按键发给了远端 tmux 里的
Claude Code。

所以本切片的第一条是 **F199：点文件面板即夺键盘焦点**，它是另两条（F200 的 F2
入口、F202 的 Del/Shift+Del）和既有 F5 的**共同前提**。先做它，其余才有意义。

**这类 bug 的一般形状值得记下**：功能实现了、测试也绿，但**驱动它的那个前置
状态没有任何入口能到达**。单测覆盖的是「焦点在面板上时按 F5 会怎样」，没有一条
测试问过「焦点怎么才会到面板上」。

## 2. grilling 定下的决策

### D1 F199 的触发判据是「按下」而不是「点中某一行」

点空白、点栏头、右键，都算。理由：用户的心智是「我在跟这块面板打交道」，
而不是「我选中了一行」。右键那条尤其重要——F185 已经确立了「右键先夺焦点再
操作」，这里只是把同一条规矩铺到整块面板。

活动栏（远端/本地）由面板自己就地改在 `PanelFrame::active_column` 上，
`UiActions::files_focus_click` 只带「焦点归属」这一件 `app.rs` 才管得了的事。

### D2 F200 就地改名，不弹框；旧的改名对话框整个删掉

用户明说「不需要弹出提示框，就在 SFTP 中改名」。于是：

- `FilesDialog::Rename` 变体、它的 `modal()` 臂、`cancel_op` 臂、三条测试，**全删**。
  不保留「两条路」——右键菜单里的「重命名」和 F2 走同一个入口
  （`FileAsk::Rename` → `PaneState::begin_rename()`）。
- 右键菜单标签从「重命名…」改成「重命名」：这套 UI 里省略号的含义是「会弹框」。

### D3 预选中主干名、保留扩展名

改名十有八九是改主干（`report.txt` → `report-final.txt`）。扩展名跟着一起被选中
的话，用户每次都要先按一下 End 再往回删。

与 F201「路径条整条全选」不矛盾：路径条的常见操作是**整条换掉**（粘一条新路径
进去），文件名不是。两者共用 `select_all` 一个出口，只是传的长度不同。

### D4 Shift+Del 一律免确认，文件和目录一视同仁

我推荐的是「文件免确认、目录仍弹框」（目录是递归删，破坏面大）。**用户否掉了**，
选「一律免确认」。理由（用户的）：他拿这个键清一批临时文件，里面就是有目录；
一条条确认反而会养成「闭眼点确定」的习惯，那比没有框更危险。

这是**设计 D17（远端删除不可逆、必须确认）唯一的明示例外**，在
`files_dialog.rs` 的模块头上写明了，免得下一个人当 bug 修掉。代价是手滑按到
Shift 就真的没了，所以那条路必须报一句带计数的吐司。

### D5 吐司说「正在删除」而不是「已删除」

**这一条与 grilling 时的约定不同，是实现期改的。**

当时约定的文案是「已删除 N 个文件、M 个目录」。写的时候发现：删除是异步派发的，
`UserEvent::SftpOpDone` 回来时已经有「已完成」吐司（成功）或错误卡片（失败）。
在字节刚发出去的那一刻宣布「已删除」，链路一断就是一条假消息——而这个项目的
主场景恰恰是高延迟代理链路。

改成「正在删除 N 个文件、M 个目录」，配一条守护
`the_no_confirm_toast_says_it_is_under_way_not_that_it_is_done`。

### D6 F203 新开一个 token，不复用 `bar_status`

弹窗原先蹭 `bar_status`（`#181b26`），对 `term_bg`（`#14161f`）只抬 7/255。

不把 `bar_status` 整个调亮：状态栏与会话管理器内框也用它，那两处贴在 `panel_bg`
上本来就分得清，跟着变灰纯属误伤。新增 `modal_bg` = 用户指定的 `rgb(63,63,63)`。

**这是一个中性灰，与 F80 冻结色板的冷调蓝紫不同源。**这一点是明知的取舍：实报的
问题是「找不到」，醒目度优先。已登记进冻结色表
（`2026-07-29-ui-visual-baseline-design.md` §2.1）。

### D7 ✕ 走 `egui::Window::open()`，且它就是「取消」

不自己在正文里画一颗：egui 把 `open()` 的 ✕ 画在标题栏右上角、位置与系统窗口
一致；自己画会掉进标题栏的内边距里，视觉上是两颗关闭按钮打架。

「✕ = 取消」意味着两个入口共用一份处置逻辑（`cancel_op`），其中两个框
（有在途工作的那两个）关掉时要发出撤销 `FileOp`。两处各写一遍的话，迟早有一处
漏掉后加的变体——这就是 `cancel_op` 抽成纯函数的全部理由。

### D8 F204 的 Ctrl+S 等价于按那颗按钮，**包括它按不动的时候**

按不动时不是静默无事，而是说出为什么（未连接 / 没改动 / 正在保存）。
「快捷键 = 按钮」这条等价关系本身就是守护测试的判据，比分别断言两条路径更难
写出恒绿。

## 3. 三个「编译过、测试绿、跑起来才错」的坑

### 3.1 面板里的输入框必须登记成 `Modal`（T8）

`Modal::FilesRename` 要同时进**五处**：枚举变体、`Modal::ALL`、`modal_open` 的
`match` 臂、完备性测试的 `match` 臂、完备性测试的驱动循环。漏了的话那个输入框
一个键都收不到，退格还被 `handle_panel_key` 抢走去做别的事。

这是 T8 的老账：判给终端/面板的键盘事件不喂 egui，所以 egui 里的输入框必须由
`modal_open` 这张表**显式**声明自己需要键盘。

### 3.2 行内输入框的高度必须正好是 `ROW_H`

`Ui::put` 收尾按子 ui 的 `min_rect` 推进布局光标，而 `centered_and_justified`
（`put` 内部用的布局）会让 `TextEdit` **填满**给它的矩形——所以那个 `min_rect`
就是我们传进去的 `name_rect`。矮 1pt，它下面每一行就整体上移 1pt。

`ScrollArea::show_rows` 的虚拟滚动只管起始偏移、不检查行与行之间怎么排，
**编译/测试/日志全不吭声，只有人眼能看见**。

第一版是画成 `ROW_H - 2`、再用 `ui.advance_cursor_after_rect(row_rect)` 补偿。
**变异验证时发现它是恒绿的**：删掉那句补偿，测试照样过——漂移量正好是 1pt，
低于测试的分辨率（约 11pt）。改成让 `name_rect` 高度恰为 `ROW_H`，行距由几何
构造保证，补偿那句删掉；测试的自证改成把 `ROW_H` 写成 `ROW_H * 2.0`，这回杀得掉。

**教训**：靠一句补偿调用维持的不变量，很难写出杀得掉的守护；能改成由构造保证的，
就别留补偿。

### 3.3 改名编辑态存的是**原名**，不是行下标

点一次列头 `entries` 就重排了，下标会让输入框跳到另一个文件上——而改名和删除
一样属于「对错文件下手」那一类不可逆操作。与 `PaneState::selected` 存身份是同一
条理由。

配套的生命周期：`begin_load`（换目录）、`invalidate`、以及 `accept` 后发现那一行
已经不在了，三处都要清掉编辑态。

还有一条**借用顺序**的坑：`state.rows()` 借着 `&state.entries`，所以
`state.rename_edit.take()` 必须发生在 `rows()` **之前**，否则 E0502。

## 4. 单一真值出口

本切片新开了两个「同一件事有两个入口」的地方，各自收口成一个函数：

| 事 | 出口 | 两个入口 |
|---|---|---|
| 这次要删哪些东西 | `PaneState::delete_targets()` | 确认框 / Shift+Del |
| 删除的计数文案 | `files_dialog::counted()` | 「将删除 …」/「正在删除 …」 |
| 取消一个弹窗 | `files_dialog::cancel_op()` | 「取消」按钮 / 标题栏 ✕ |
| 进编辑态就全选 | `files_panel::select_all()` | 路径条（整条）/ 改名框（主干） |

## 5. 人工验收清单（无头环境验不了）

1. 点一下文件面板的任意位置（含空白、栏头、右键），再按 **F5**——列表刷新，
   而不是把 F5 发给远端。
2. 选中一个远端文件按 **F2**：那一行原地变输入框，主干名高亮、扩展名没被选中。
   敲字→回车，文件改名；再试一次敲 Esc，放弃。输入 `a/b` 时红框 + hover 说明。
3. 改名框展开的那一帧，**它下面各行不许上下抖一下**。
4. 选中若干文件按 **Del**：弹确认框；按 **Shift+Del**：不弹框、直接删，
   左下角出现「正在删除 N 个文件、M 个目录」，随后是「已完成」。
5. 在终端 pane 上弹删除确认框：底色 `#3f3f3f` 是否**一眼就能找到**；框里的次要
   说明文字是否清楚（换了亮一档的 token）；标题栏右上角 ✕ 点了等于「取消」。
6. 打开「编辑文件」窗口：是否居中；右上角 □ 点了能最大化、再点还原（图标要跟着
   变，且**不能是豆腐块**）；✕ 能关；底部那行没有多余的关闭按钮。
7. 在编辑器里改点东西按 **Ctrl+S**：存到远端。没改动 / 没连上时按 Ctrl+S，
   要给出说明而不是毫无反应。
