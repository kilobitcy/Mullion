# 设计:远端栏新建文件(F219)+ 远端内复制/剪切/粘贴(F220)

> 2026-09-04。来源:用户对 v0.1.93 提的两条优化 ——「文件面板/远端可以新建文件」
> 「文件面板/远端可以选中文件复制粘贴,只在远端」。

## 一句话

远端栏补齐两件本地文件管理器里天经地义、而这里还没有的事:**建一个空文件**,
和**在同一台机器上把东西拷/挪到另一个目录**。两者都只在远端栏成立(设计 D5:
本地文件管理外包给资源管理器)。

## 一、已拍板的五条边界

brainstorm 时逐条问过,不再重开:

| # | 决策 | 否掉的备选与理由 |
|---|---|---|
| B1 | **作用域 = 同一标签、同一连接** | 否掉「跨标签/跨主机」:跨主机时数据必须经客户端中转(下载再上传),等于在高延迟代理链路上走两遍,实现量翻倍(要复用传输队列 + 冲突框 + 进度),而用户要的是「只在远端」 |
| B2 | **复制走 exec `cp -a` 快路径 + SFTP 逐文件回退** | 与 F57 `remove_tree` 完全对称。否掉「一律 SFTP 中转」(同机拷贝把每个字节拉到 Windows 再送回去,慢两个数量级);否掉「只走 exec」(sftp-only 账号上功能残缺) |
| B3 | **同名冲突:粘贴前一次性检查 + 一个批量框** | 三选一「覆盖 / 跳过同名 / 保留两者」,对整批生效。否掉「一律自动保留两者」(想覆盖时得先手动删);否掉「逐条弹框」(逐条问就没法用一条 `cp -a` 包干,快路径优势被拆掉) |
| B4 | **剪贴板 per-tab** | 剪贴板里的路径永远属于当前这条连接,不会指到另一台机器上不存在的路径。否掉「全局一份 + 同主机同用户才可粘」(多一层「连接身份相等」判据要维护) |
| B5 | **新建走「先命名后建」的幽灵行** | 打字零等待,Esc 放弃时远端一个字节都没动。否掉「先建后改名」(资源管理器行为):高延迟链路上要两次往返才能开始打字,且 Esc 会在远端留一个空文件 |

## 二、F219 就地新建文件

### 交互

- 入口两个:远端栏右键菜单「新建文件」**(无省略号)** 与 `Ctrl+N`。
  省略号在这套界面里的意思是「会弹框」(F200 定的),就地编辑不带。
- 本地栏按 `Ctrl+N` **静默不动**,不转投远端栏 —— 与 Delete/F2 同一条判据
  (用户看着本地栏按键、结果动了远端,是这一片能造成的最坏后果)。
- 列表**第一行**插一个只存在于本地的输入行,回车提交、Esc 放弃、点别处放弃。

### 落点

**`files/state.rs`**:新增 `new_edit: Option<NameEdit>`。

- 与 `rename_edit` **互斥**:进其中一个就清掉另一个。两个 `TextEdit` 同时活着
  会互抢键盘焦点 —— `path_edit` 的文档里记着 F131 实测过的同款事故
  (先进编辑态那栏永远 `lost_focus()` 不了、退不出来)。
- 生命周期:`begin_load` / `invalidate` 里清(换了目录之后,回车拼出来的是
  **另一个目录**的路径);`accept` 里 **不清** —— 它不绑任何已有行,刷新时
  清掉会把用户正在打的字吞掉(这条与 `rename_edit` 的处置**故意不同**,
  后者绑着一个具体的行,那行没了就必须清)。

**`ui/files_panel.rs`**:

- `show_rows` 的行数给 `rows.len() + 1`;`ix == 0` 时画输入行,其余取
  `rows[ix - 1]`。**索引偏移是这一节最容易静默错行的地方**,配独立守护。
- 进入新建态那一帧把垂直滚动偏移钉到 0(输入行在第一行,看不见就等于没有)。
  只在那一帧钉 —— 无条件钉的话滚轮就废了(F218 已经踩过一次)。
- F218 的 `scroll_offset` 换算(`ix as f32 * ROW_H`)在幽灵行激活时 `ix`
  要 +1 —— 边界很窄(新建态跨着一次 reveal 完成),但错了就是静默偏一行。
- 输入框构造与 `rename_row` 共用一份(抽 `name_edit_row`):焦点用一次性
  `focus_pending`、高度正好 `ROW_H`(矮 1pt 下面每行整体上移且**全程不报错**,
  见 F200)这两条前提两处都要,各写一遍必然漂移。

**校验**:复用 `files_dialog::validate_name`(挡 `/`、`.`、`..`、空),
**再加一条本地判重** —— 目录里已有同名就红框提示、不提交。这件事本地就知道,
不必往返一趟等服务端回 Failure。

**动作**:`FileAction::NewFile(RemotePath)` → `FileOp::NewFile(RemotePath)`。
路径是**绝对路径,在面板里用同一个 `cwd` 拼好**:从开始输入到敲回车中间用户
完全可能换目录,app 侧再拿「当前 cwd」拼就是在另一个目录里建文件(同 F200)。

**`mullion-ssh`**:`SftpClient::create_file(&RemotePath)`,flags 用
`WRITE | CREATE | EXCLUDE`。**这里要 `EXCLUDE`** —— 与 `open_write` 刻意不带
的理由正好相反:传输通路的覆盖与否由上层冲突策略决定,而「新建」撞上已存在
必须失败,不能悄悄把别人的文件截断成 0 字节。

**建成之后**:`SftpOpDone` 成功那条路复用 F218 的 `reveal_pick`/`scroll_to`
机制,把光标与选中落到新文件上 —— 建完之后用户第一件事多半是编辑或改权限,
让他在刷新后的列表里重新找一遍等于白建了一半。

**`Modal::FilesNewName`** 新增一档,五处一处不落(T8:漏了就是这个面板一个键
都收不到,而且是永久性的)。Modal 完备性表要改两处(F148 的已知坑)。

## 三、F220 远端复制 / 剪切 / 粘贴

### 剪贴板

`files/clip.rs`(新,纯逻辑、零 IO):

```rust
pub enum ClipMode { Copy, Cut }
pub struct RemoteClip {
    pub mode: ClipMode,
    /// 绝对路径 + 是不是目录。**复制那一刻就拼好** —— 之后用户换目录不影响。
    pub items: Vec<(RemotePath, bool)>,
}
```

挂在**标签**的文件面板状态上(B4)。`is_operable()` 过不了的名字**不收进来**
(同删除/传输的判据):收进来只会让用户以为「拷了 5 个」,其实有一个必然失败。

### 入口

- 远端栏:`Ctrl+C` / `Ctrl+X` / `Ctrl+V`,以及右键菜单三项。
- 粘贴项在剪贴板为空时**置灰 + 说明理由**,不是消失(D3-2:悄悄少一项,
  用户只会以为程序坏了)。
- 本地栏三个键一律静默(同 F219 那条理由)。
- 剪切之后源行画淡 —— 否则用户看不出自己刚才按的是剪切还是复制。

### 粘贴的三步

0. **先过一道纯函数闸门:目标是任一源的自身或子孙 → 整批拒绝**,一句 Warn
   toast 说明理由。`cp -a A A/sub/` 在远端会被 cp 自己拦下,但那是靠远端
   兜底;**SFTP 回退是我们自己写的递归 —— 边列源边往源的子孙里写,会无限
   递归**,必须在发出任何请求之前就挡掉。判据是绝对路径的字节前缀比对,
   `/` 边界对齐(`/a/bb` 不是 `/a/b` 的子孙)。
1. **预检查**:后台列一次目标目录,与剪贴板里的末段名字取交集。
   **不用面板里那份 `entries`** —— 它可能是几分钟前的,而覆盖不可逆。
   这是新的一段异步:结果经新的 UserEvent 回流,按 generation 路由,
   标签没了就丢弃(T11 那条兜底:挂在在途 task 上的判定要能被回收)。
2. **有冲突才弹** `FilesDialog::PasteConflict { targets, choice }`:列出撞了
   哪几条,给「覆盖 / 跳过同名 / 保留两者」三选一,对整批生效。
   **取消 / 标题栏 ✕ = 整批不动**(`cancel_op` 里是 `None` 臂 —— 粘贴还没
   发出去,没有挂起的工作要处置),剪贴板保留。进对话框完备性表(两处)。
   - **同目录复制**必然全撞 → 直接走「保留两者」,不弹框(问用户「要不要覆盖
     自己」没有意义)。
   - **同目录剪切**是空操作 → 一句 Warn toast 收掉,不发任何请求。
3. **执行**:`mullion-ssh/src/copy_tree.rs`(新,与 `remove_tree.rs` 完全对称)。
   先 `exec`,被拒(sftp-only 账号)才回退 SFTP 逐文件。

   | 处置 | Copy | Cut |
   |---|---|---|
   | 覆盖 | `cp -af -- src… dst/` | `mv -f -- src… dst/` |
   | 跳过同名 | **客户端把冲突项从清单里滤掉**,剩余走裸 `cp -a` | 同左,剩余走裸 `mv` |
   | 保留两者 | 逐条 `cp -a -- src 'dst/新名'`,`&&` 串起来 | 逐条 `mv -- src 'dst/新名'` |

   - **「跳过同名」不用 `-n`**:预检查本来就算出了冲突集合,过滤后发裸命令
     即可。`-n` 是个退出码陷阱 —— coreutils 9.2 把「跳过时的退出码」改成
     非零、9.3 又改回,撞上那个版本会被 `ExecOutcome::succeeded` 判成失败,
     给用户报一张莫名其妙的错误卡片。过滤后清单为空 = 空操作,toast 收掉。
   - SFTP 回退:Copy 走 `open_read` + `open_write` 中转并把源 mode 用
     `set_permissions` 补上;Cut 走 `rename`,跨设备失败(EXDEV)再退成
     copy + `remove_tree`。
   - **绝不跟随符号链接**:列举用 `list_dir`(readdir = lstat 语义),遇到
     `EntryKind::Symlink` 当叶子处理,不进去。这是 `remove_tree` 里最重要的
     那条不变量,复制这边同样成立(拷进去等于把整个目标目录复制一遍)。
     回退路上链接用 `read_link` + `symlink` 原样重建 —— 锁定版
     russh-sftp 2.4.0 两个 API 都有(已按「API 漂移」条款核实签名)。
   - 命令拼接**复用 `exec::shell_quote`**,不另写一份:那是「漏一个元字符
     就是远端任意命令执行」的地方。
   - 路径 `as_wire()` 过不了的**一条都不发**(同 `remove_tree` 开头那道门)。
4. **回流**:发出时报一句 Busy 档 toast「正在复制 N 项…」——**措辞不用
   完成时态**,字节这会儿才刚出去,成败要等事件回来(F213 起 toast 档位是
   必填参数,由编译器当闸门)。完成后刷新目录。
   **Cut 成功清空剪贴板,Copy 保留**(可以连粘多次)。「成功且是剪切」这个
   判据要求完成事件里带得出「这次完成的是哪种操作」—— 现有
   `SftpOpDone { generation, result }` 没有这个信息,要么扩它、要么给粘贴
   走一条带 op 种类的新事件,plan 里定;**不许**在发出那一刻就乐观清空
   (T11:非 Completed 意味着压根没发出去)。

### 「保留两者」的命名

在 `clip.rs` 里算,纯函数:`a.txt` → `a (副本).txt` → `a (副本 2).txt`;
目录不切扩展名(`logs` → `logs (副本)`)。半角括号,「副本」在 GBK 内,
不触 T9(字形白名单)。

### 取消

`cp -a` 是一条命令,中途没法取消 —— 与现有 `rm -rf` 一致,不额外做。

## 四、测试

**纯逻辑(零窗口零网络)**

- 唯一名生成:扩展名保留、第二次撞变 `(副本 2)`、目录不切扩展名。
- 冲突集合:只按末段名字比,大小写敏感(远端是 Linux)。
- **自身/子孙闸门**:目标 = 源自身、目标 = 源的子孙、`/a/bb` 不算 `/a/b`
  的子孙(`/` 边界)、根目录做源。这条守护的是「SFTP 回退不无限递归」。
- 同目录剪切 = 空操作(计划为空,一条请求都不发);「跳过同名」过滤后
  清单为空同样是空操作。
- `new_edit` 与 `rename_edit` 互斥;`begin_load`/`invalidate` 清、`accept` 不清。

**面板层**

- 幽灵行占第一行,且**索引偏移正确**:点第二行选中的必须是 `rows[0]`。
- 重名不提交(本地判重那条闸门)。

**app 层**

- 本地栏 `Ctrl+N`/`C`/`X`/`V` 全静默。
- `Modal::FilesNewName` 进了 `Modal::ALL` 且有独立的 `modal_open` 臂。
- 粘贴分支里确实**先做了预检查**(源码切片守护,防「直接 cp 覆盖」退化)。
- Cut 成功清剪贴板、Copy 不清。

**`mullion-ssh` 集成层**(假 SFTP 服务端,`tests/common/sftp_server.rs`)

- 扩服务端让它认 `cp -a` / `mv`(现在只认 `rm -rf -- `),在内存树上真的执行。
- 四条:exec 快路径下**一条 SFTP 写请求都不发**;exec 被拒时回退;两条路都
  不跟随符号链接;脏名字(空格/引号/`$`)引号正确。

守护测试一律要能**自证变红**(改坏实现后必须失败),写完做变异验证;
变异验证**前先 commit**(已经被 `git checkout` 吞过五次未提交的编辑)。

## 五、交付

改动落在 `mullion-app`,按项目交付约定一条龙:升 patch → 跑绿
(`cargo test --workspace` + `clippy -D warnings`)→ 交叉编译 + objdump 验收 →
签名 → 发 GitHub Release(**v0.1.95**)→ 报链接和人工验收清单。

**无头容器里验不了、必须写进人工验收清单的**:

- 真机上 `cp -a` / `mv` 的实际行为(尤其目标是别的挂载点时的 EXDEV 回退)。
- 幽灵行在列表里的视觉位置与行高对齐(矮 1pt 那类漂移只有人眼看得见)。
- 剪切后源行「画淡」的实际对比度。
- 高延迟链路上「打字零等待」是否真的成立。
