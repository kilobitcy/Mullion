# SFTP 节点分档 + 隧道表单重排 + 表单布局规范（F118 / F119）

> 2026-08-11。切片 T-c（v0.1.30）之后的下一片。
> 相关：F116（模式条）、F110~F117（隧道）、F50~F57（SFTP 侧栏，**本切片不做**）、
> spec §A（协议筛选 chips 的否决理由，本切片使其失效）。

## 背景

四件事，两条主线。

**主线一：SFTP 节点有了自己的一档。** 库里的 `SessionRecord` 早就带
`connection.protocol: Ssh | Sftp`，但 `Sftp` 的拨号从未实现
（`session_map.rs` 直接返回 `SftpNotSupported`），编辑器里那一项标着「sftp(未实现)」。
spec §A 因此否掉了「左栏协议筛选 chips」，理由是「库里所有会话实际都是 SSH，
单值筛选器是纯噪音」。现在的诉求是把 SFTP 提成模式条第三档，先把**节点管理**
（连什么机器、用什么凭据、走不走跳板）做出来，文件传输本体（F50~F57）照旧推后。

**主线二：隧道表单欠了一次排版。** `tunnel_editor::show` 是切片 T-a 赶出来的：
七个字段一路 `ui.horizontal(label + widget)` 平铺，没有分节、没有对齐的标签列、
宽度是硬编码的 `80.0 / 180.0 / 70.0`、间距是裸 `6.0 / 10.0`。而会话「连接」页在
走查 P2-b1/b2 里已经建立了一整套骨架（分节 + 两列 Grid + 88px 定宽标签列 +
`field_w` 三档宽度 + `SP_*` 五档间距）。两边看起来不像一个软件。

这两条在**需求 4** 上交汇：那套骨架目前只以私有函数和文档注释的形式活在
`fields.rs` / `metrics.rs` 里，没有对外的规范，也没有任何机械约束。所以本切片
把它抽成公共构件 + 一份规范文档 + 两条扫源码的守护测试。

## 决策

### D1 SFTP 节点复用 `SessionRecord`，按 `protocol` 分流

**schema 不动，仍是 v7。** SFTP 节点就是 `protocol == Sftp` 的会话记录，与 SSH
会话共用一张表、一套分组 / 凭据 / 代理 / 跳板链 / 图标。

否掉的备选：

- **独立 `SftpNodeRecord` + schema v8。** 分组、凭据入库、代理、跳板链、图标那
  一整套要么复制一遍要么抽公共结构，外加一次迁移。而这两类节点的连接参数
  **完全同构**——差别只在连上之后开什么 channel。为一个不存在的差异付迁移的账
  不划算。
- **一条会话同时是 SSH 和 SFTP（两个能力位）。** 需要改 `Protocol` 的语义、动
  迁移、动所有读 `protocol` 的地方；而且「经由会话」下拉的过滤条件会从
  「是 SSH」变成「勾了 SSH」，语义更绕。

代价（明确接受）：一台机器既要当 SSH 会话又要当 SFTP 节点，就得建两条记录。

### D2 分流的唯一真源是一个纯函数，且列表与键盘顺序**共用**它

```rust
pub enum ManagerMode { Sessions, Sftp, Tunnels }   // 模式条顺序：会话 | SFTP | 隧道

/// 这一档该列哪种协议的记录。`Tunnels` 不列会话，故为 None。
pub(crate) fn protocol_of(mode: ManagerMode) -> Option<Protocol>
```

`list::show` 与 `list::visible_order` **都**加一个 `protocol: Protocol` 参数，
内部 `.filter(|r| r.connection.protocol == protocol)`。

两处都要过滤，不是冗余：`visible_order` 是走查 16 的 `↑/↓` 键盘顺序的真源，
只过滤渲染那一侧，方向键会把选中态跳到当前页**根本看不见**的记录上——用户看到
的是「按了下箭头，右栏表单换了一条陌生的会话，左栏却没有任何行高亮」。

不在调用方先 `filter().cloned().collect()` 再传切片：那是每帧克隆整份会话表，
且两个调用点各写一遍过滤条件，迟早分叉。

**键盘动作同时补上模式门（既有漏洞，本切片正面触及）。** `keys::scan` 的
`Prev/Next/Open/Tab` 四个动作目前在 `mod.rs` 里**没有任何模式判断**：现在
站在隧道页按 `↑/↓`，走的仍是会话列表的 `visible_order`，会对一条**看不见**
的会话发 `pending_switch`（会话侧表单脏着的话还会凭空弹出确认框）；Enter
会连接一个看不见的会话；`1~4` 会切一个看不见的编辑器的 Tab。这是切片 T-a
引入 F116 时漏的。修法：四个动作按模式分流——`Sessions`/`Sftp` 用协议过滤
后的顺序（`Open` 在 Sftp 下不发，见 D4）；`Tunnels` 下四个动作**一律
no-op**。隧道列表的键盘导航是新功能，不进本切片。守护测试：Tunnels 模式下
按 `↓`/Enter，断言 `pending_switch` 与 `connect_request` 均为 `None`。

### D3 协议字段在编辑器里改成**只读**

会话页恒 `ssh`，SFTP 页恒 `sftp`，显示但不可改。

可改的话，一条记录会在保存那一刻从当前列表消失、出现在另一页——用户看到的是
「我点了保存，会话没了」。更糟的是引用了它的隧道会当场变成「经由一个 SFTP
节点」，而那条隧道昨天还是好的。

代价：移除了现有的「把会话协议选成 sftp」这个能力。它本来就通向
`SftpNotSupported` 的死路，编辑器里那句「sftp 尚未实现，连接会按 ssh 处理」
随之删除。**要改协议就新建一条**，与 D1 接受的代价同源。

已有库里若存在 `protocol == Sftp` 的记录，它会从会话页搬到 SFTP 页（数据一个
字段不丢，只是换了页显示）。预计影响为零（spec §A 记录过「库里所有会话实际
都是 SSH」），但列在人工验收清单里。

### D4 SFTP 页只有节点管理，连接入口置灰并说明原因

- 「连接」按钮 `enabled(false)` + `on_disabled_hover_text("SFTP 传输尚未实现（F50）")`。
- 键盘 `keys::Action::Open`（Enter）在 `ManagerMode::Sftp` 下**不发**
  `connect_request`——否则鼠标挡住了、键盘却放行，等于置灰只是装饰。

不走「点了就按 SSH 连」：SFTP 页点一下开出个 shell，语义上是错的，且会让用户
以为 SFTP 已经可用。

### D5 编辑器在 SFTP 模式下少一页，且 Tab 下标必须走映射表

SFTP 节点画 `连接 / 认证 / 图标` 三页。「登录后」整页是发 shell 命令与 tmux
附着（F40~F44），对 SFTP 没有落点，画出来等于让用户配一堆永远不会执行的东西。

**实现陷阱**：`TAB_CONNECT=0 / TAB_AUTH=1 / TAB_AUTOMATION=2 / TAB_APPEARANCE=3`
是**下标常量**（`editor.rs` 头上写明这是既有技术债）。隐藏中间那一页之后，
不能再用 `TABS.iter().enumerate()` 画 Tab——第三个画出来的是「图标」，但
`enumerate` 给它的下标是 2，点下去打开的是「登录后」。必须先算一张
`visible_tabs(mode) -> &'static [usize]`（元素是原始下标），渲染与
`ui_state.editor_tab` 的读写都过它。守护测试：SFTP 模式下点第三个 Tab，断言
`editor_tab == TAB_APPEARANCE`。

`validate::tab()`（把用户导向有错的那一页）**不需要改**：必填项只有名称 /
主机 / 用户名，`Missing::tab()` 在类型上只可能返回 `TAB_CONNECT` 或
`TAB_AUTH`，两页在 SFTP 模式下都在。配一条防漂移断言（`Missing` 全字段
置位时返回值 ∈ 可见集）钉住这个前提——将来有人给「登录后」页加必填项时，
这条会先红。

### D6 「经由会话」只列 SSH 会话

`tunnel_editor::show` 的下拉过滤 `protocol == Ssh`。隧道的实现是
`channel_open_direct_tcpip` / `tcpip_forward`，SFTP 节点跟它没关系。

已经指向 SFTP 节点的隧道只可能由手改 TOML 造出。**不静默改选、不静默清空**，
沿用 D3（切片 T-a）那条既有的悬垂处理：保持原值 + 红字说明。措辞与「已删除的
会话」区分开：`⚠ 该会话是 SFTP 节点，不能用于转发`。

### D7 重复检测不动，但 `disambiguate` 只看当前页

`dedupe::duplicate_of`（保存时提醒「你存重了」）**已经**把 `protocol` 纳入
比较，同一台机器建 ssh + sftp 两条不会互相报重复——按 D1 的代价，这正是推荐
做法，不能给它挂警告。它继续拿**全表**。

`dedupe::disambiguate`（列表行「看起来一样，追加区分信息」）拿**当前页过滤后**
的集合：跨页的两行永远不会同框出现，追加区分信息只是噪音。

### D8 抽公共表单构件 `form.rs`

新建 `ui/session_manager/form.rs`，把 `fields.rs` 里的 `section` / `grid` /
`required` / `field_error` **原样搬过去**（`pub(super)`，逻辑一字不改，含那几段
写了很久的文档注释），`fields.rs` 改为 `use`。会话页与隧道页共用同一份。

搬迁本身不改行为，`fields.rs` 现有的渲染测试就是这次的回归网。

否掉「隧道表单自己写一份 Grid」：需求 4 要的是规范能落到代码上。没有共享构件，
「标签列 88px」「分节前一条细线」这类规则只能靠人看，下个切片照样漂。

### D9 隧道表单重排为四个分节

```
[转发]
  类型 *          (下拉)
  经由会话 *      (下拉，只列 SSH 会话)

[侦听]
  本机侦听端口 *  (FIELD_W_S)
                  灰字：连本机这个端口，流量从远端主机发出
  ☐ 允许同网段其他主机连这个端口
                  红字 / 黄字警告

[目标]            ← Dynamic 时整节不画
  目标主机 *      (FIELD_W_M) : (FIELD_W_S)
                  灰字：目标主机名由远端主机解析

[其他]
  说明            (FIELD_W_L)
──────────────────
  [保存]  [删除]
```

**只动排版**。原样保留、一个字不改的：`wording()` 随类型翻转的标签（D12 的
「填反了就连不通、而 `-R` 的错误还出在远端」是这个功能第一道防线）、
`expose_warning()` 的两种语气（D5/D9：`-L` 说风险并点名具体目标，`-R` 必须写明
「无法验证」）、`build_tunnel_draft()` 的全部校验。它们各自的穷举测试不动。

排版侧的改动：宽度换 `field_w(available, FIELD_W_S/M/L, reserve)`；间距全换
`SP_*`；必填项加 danger 色星号（类型 / 经由会话 / 侦听端口 / 目标，Dynamic 无
目标节）；端口非法从「点保存后弹顶部通知」改为**字段下方内联红字**，规则与会话
页 `port` 一致（不看 `touched`：填错就是填错了，跟填到哪一步无关）。

### D10 规范落盘 `docs/ui-form-guidelines.md` + 两条机械守护

九条规则（每条给「规则 / 为什么 / 谁保证」）：

1. 表单骨架三层：分节 `section` → 两列 `grid` → 88px 定宽标签列。
2. 宽度只用 S/M/L 三档，且必须过 `field_w`（扣预留 → 取上限 → 夹下界，三步缺一
   不可，来源见 `metrics.rs`）。
3. 间距只用 `SP_XS/S/M/L/XL` 五档，禁止裸数字。
4. 必填项标签后跟 danger 星号。
5. 内联红字挂**输入列**，不挂标签列（挂标签列会被读成「这一行的标签」）。
6. 灰字说明挂字段下方，同样不占标签列。
7. **危险措辞规则**：能验证的后果，说风险并点名具体目标；验证不了的，必须写明
   「无法验证」及原因。来源是 `-R` 的 `GatewayPorts`（F112）与 F43 拒绝给环境
   变量加密——两次都是「不给用户一个我们证明不了的安全承诺」。
8. 空态文案告诉用户下一步做什么，不承诺做不到的事（来源：会话列表空态那条
   「不许暗示有导入功能」的测试）。
9. 禁用的控件必须给 `on_disabled_hover_text`，说明为什么点不动。

机械守护（新测试文件，扫 `crates/mullion-app/src/ui/session_manager/*.rs` 源码），
两条统一同一个判据——**参数不得是数字字面量**：

- `add_space(` 后不得跟数字字面量（`SP_*` 与表达式放行）。
- `desired_width(` 后不得跟数字字面量（`field_w(...)`、`FIELD_W_*`、
  `f32::INFINITY`、局部变量放行）。

不用「只允许 `field_w`/`FIELD_W_*`」这种白名单式判据：`mod.rs` 的凭据输入框
是先 `let w = field_w(...)` 再 `desired_width(w)`——最规范的写法反而会被文本
匹配拦下。改挡字面量后这三处自然放行。**局限写进文档**：字面量判据挡不住
`let w = 80.0` 这种绕行，也挡不住「用了常量但选错档位」——机械守护是第一道
网，不是全部，其余靠评审。

既有违规的实扫结果（2026-08-11，共 **23 处**、6 个文件：20 处 `add_space`
+ 3 处 `desired_width`）与处置：

- **等值替换（零视觉变化，10 处）**：`4.0`→`SP_XS`（`tunnel_list` 1、`list` 2、
  `editor` 1、`fields` 1）、`8.0`→`SP_S`（`list` 1、`editor` 4）。切片 4 机械替换。
- **`tunnel_editor.rs` 的全部裸数字（9 处）**：`6.0`×5、`10.0`×1、
  `desired_width` 3 处。切片 2 重排时消灭，不做等值替换。
- **不在五档刻度上的其余值（4 处）**：`tunnel_list` 的 `2.0`、`mod.rs` 与
  `editor.rs` 的 `6.0`×3。进**行级白名单**（带「等下次视觉走查统一」的理由），
  本切片**不改数值**——强行归到最近档是未经人工验收的视觉变化，「顺手调间距」
  正是 Scope Discipline 要挡的事。白名单是代码，评审看得见，下次走查清空。

## 不做什么

- **F50~F57 SFTP 侧栏本体**（目录浏览、上传下载、并发通道）。本切片只到节点管理。
- **隧道 `autostart`**。`TunnelRecord.autostart` 字段在数据层和表单缓冲里都有，
  但全项目只出现在 `Default` 与测试构造里，**没有 UI 入口也没有运行时消费**，
  恒为 `false`。它需要一个新 F 编号和独立切片（含「会话连上之后才能启」的时序
  问题）。本切片不碰，只在这里点名。
- **隧道表单的脏标记 / 保存按钮禁用**。会话页有（`is_dirty` + baseline），隧道页
  从来没有。补它是新增行为，不在「优化界面」的范围内。
- **左栏协议筛选 chips**（spec §A）。模式条已经是协议轴，再加一层筛选是重复。
  §A 的否决理由要**改写**：不再是「只有一个有效值」，而是「模式条已经承担了这
  个轴」。
- **把浅色主题 / 色板搬进 `ui-form-guidelines.md`**。色板在 spec §4.6（F80~F85）
  已有真源，规范文档只引用，不复制——两份色值一定会分叉。

## 测试

纯函数（无 GPU）：

- `protocol_of` 的三档映射穷举。
- `visible_tabs(mode)` 在 Sftp 下不含 `TAB_AUTOMATION`，且三个元素依次是
  `TAB_CONNECT / TAB_AUTH / TAB_APPEARANCE`。
- `visible_order` 在给定协议下只返回该协议的记录（自证变红：去掉 filter 即红）。
- `Missing` 全字段置位时 `tab()` 的返回值落在 SFTP 可见 Tab 集内（D5 防漂移）。

egui 渲染（`egui::Context` 离屏跑，无窗口）：

- **`visible_order` 与实际渲染的行集合一致**：同一份数据分别跑两者，断言 id
  序列相等。这条钉的是 D2 那个「方向键跳到看不见的行」的失效模式。
- SFTP 模式下点第三个 Tab → `editor_tab == TAB_APPEARANCE`（D5 的下标陷阱）。
- SFTP 模式下「连接」按钮 disabled，且 hover 文案含「F50」。
- SFTP 模式下按 Enter 不产生 `connect_request`。
- **Tunnels 模式下按 `↓` 与 Enter，`pending_switch` 与 `connect_request` 均为
  `None`**（D2 键盘模式门；这条在改动前的代码上必须先红——它钉的是既有漏洞）。
- 协议字段在两个模式下都不可编辑，且显示值与模式一致。
- 隧道「经由会话」下拉列出的条目不含任何 SFTP 节点（自证变红：去掉 filter 即红）。
- 隧道指向 SFTP 节点时，红字含「SFTP 节点」且**选中值不变**。
- 隧道表单：四个分节标题都在；侦听端口填 `0` 时字段下方出现内联红字。
- 切模式仍不污染另一侧编辑器的脏标记（F116 既有测试扩到三档）。

机械守护：D10 的两条扫源码测试。

## 人工验收清单（无头环境验不了）

1. 模式条三档的宽度与对齐，`会话 | SFTP | 隧道` 在默认 880px 窗口下不换行。
2. 隧道表单重排后的观感：分节线、标签列对齐、端口框宽度是否显得空/挤。
3. 把左右分隔条拖到最窄（`LIST_MIN_W`）和最宽（`LIST_MAX_W`），隧道表单的
   目标主机 + 端口一行不被裁、不溢出。
4. **既有会话库打开后，会话页的条数与升级前一致**（若你的库里有 protocol=sftp
   的记录，它应出现在 SFTP 页而不是消失）。
5. SFTP 页新建一个节点 → 保存 → 重开程序仍在；「连接」按钮点不动且 hover 有说明。
6. 隧道页新建时，「经由会话」下拉里看不到第 5 步建的那个 SFTP 节点。
