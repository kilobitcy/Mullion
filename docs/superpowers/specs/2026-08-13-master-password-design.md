# 切片 G:主密码(F71)设计定案

> 2026-08-13。落地 spec §4.5 的 F71,收口 v0.5 里程碑最后一项。
> F48「配置跨机可用」的**硬前置**,本片只做前置,不做 F48 本身。

## 0. 一句话

给 `secrets.enc` 加一个**带盐的文件头**,让主密钥可以由用户的主密码经 Argon2id
派生;不设主密码时,格式与密钥来源**一个字节都不变**。

## 1. 问题

`master_key.rs` 现在的做法是:`OsRng` 随机生成 32 字节主密钥 → 存进 OS 钥匙串。
这满足 F70 的验收标准(磁盘上搜不到明文口令),但有一个结构性后果:

**`secrets.enc` 与这台机器的钥匙串绑死。** 把配置目录拷到另一台机器,
`sessions.toml` 能读,`secrets.enc` 永远解不开——钥匙串里没有那把密钥,
而密钥不在文件里。F48 想让用户「把配置目录整体搬走就能用」,在这个前提下
无解。

## 2. 方案

主密钥有两种来源,**由 `secrets.enc` 自己的文件头声明**,不由任何本地配置声明:

| 方案 | 密钥来源 | 文件格式 |
|---|---|---|
| `Keyring`(默认,不设主密码) | OS 钥匙串里的随机 32 字节 | `nonce(24) ‖ ct` —— **与今天逐字节同构** |
| `Argon2id`(设了主密码) | 主密码 + 盐 经 Argon2id 派生 | `magic ‖ 参数 ‖ 盐 ‖ nonce(24) ‖ ct` |

### D1 —— 方案写在密文文件头,不写在 `settings.toml`

盐必须随密文走,否则「搬走配置目录」这件事本身就白做了(spec F71 原话)。
既然盐已经在文件头,把「用哪种方案」「Argon2 参数」一并放进去是免费的,
而放进 `settings.toml` 则会引入一个**可以与密文不一致的第二真源**:
用户手改 `settings.toml` 说「没设主密码」,`secrets.enc` 却是密码加密的,
程序会拿钥匙串密钥去解,失败后报「密文损坏」——一个纯粹由二义状态制造的假故障。

### D2 —— 不设主密码时,格式一个字节都不改

一个更「统一」的做法是永远写文件头(`kdf = none`)。**否决**,两个理由:

1. spec F71 的验收标准写的是「未设主密码时与今日行为**逐字节等价**的回归测试」。
   永远写头就没有这条测试可写了。
2. 降级路径。用户装了新版又退回旧版(未签名 exe,这事会发生),旧版读不懂文件头,
   表现是「所有保存的密码都没了」。不设主密码的用户占绝大多数,不该为一个
   他们没启用的功能承担这个风险。

代价是格式检测要靠魔数试探(见 D3)。

### D3 —— 魔数试探,并承认它的概率边界

新格式前 8 字节是 `b"MULLION\x01"`(末字节 = 头版本号)。旧格式的前 24 字节是
随机 nonce。因此判据是:**以魔数开头 → 新格式;否则 → 旧格式**。

误判概率 = 随机 nonce 恰好撞上这 8 个字节 = 2⁻⁶⁴。这不是「小到可以不管」的
含糊说法,而是与「AEAD tag 被随机碰撞」同量级——真撞上了,解密也会失败,
表现是报错而不是静默读出垃圾。**写进代码注释,不靠读者自己算。**

### D4 —— 文件头布局(固定 35 字节)

```
偏移   长度  内容
0      8     magic  b"MULLION\x01"
8      1     kdf    0x01 = Argon2id   (0x00 保留,当前不写出)
9      4     m_cost u32 小端(KiB)
13     4     t_cost u32 小端
17     1     p_cost u8
18     1     salt_len u8  (当前恒为 16)
19     16    salt
35     ..    nonce(24) ‖ ct   —— 与旧格式的载荷部分完全一致
```

**参数进文件头**,不写死在代码里:今天的 19 MiB/t=2 是 OWASP 当前建议,
三年后要调。参数写死的话,调完之后所有老文件都解不开了,而症状是
「主密码突然不对了」——用户会以为自己记错了密码。

`salt_len` 单独占一字节而不是靠常量:同样的道理,盐长要变时老文件还得能读。

### D5 —— Argon2id 参数取 `Params::DEFAULT`(19 MiB / t=2 / p=1)

即 RustCrypto 跟随的 OWASP 建议值。不自己调参:调参需要在目标机器上实测,
而目标机器是用户的 Windows,不是这里。19 MiB 的内存峰值对桌面应用可忽略。

### D6 —— 设/撤主密码**不碰钥匙串条目**

设主密码时不删钥匙串里那把旧密钥。理由:删除是不可逆的,而它的存在完全无害
(没有文件再引用它);留着还让「撤销主密码」有一条不需要重新生成密钥的路。
撤销主密码时走既有的 `load_or_create`——钥匙串条目还在就复用,被用户手工清掉了
就新生成一把,两条路都正确。

### D7 —— 撤销主密码要求钥匙串**可用**,失败就不撤

`clear_master_password` 先 `load_or_create()` 拿到钥匙串密钥再重写文件。
钥匙串不可用(Linux 无 Secret Service 等)时**报错并停在主密码方案**,不静默留在
半途状态。半途状态在这里的具体后果是:内存里的密钥换了、文件还是老的,
下一次任何 `save()` 都会用错的密钥重写整个 `secrets.enc`——所有凭据当场变成
永久解不开的字节。

### D8 —— 密码错要与文件损坏**分开报**

Argon2id 方案下解密失败一律映射成 `StoreError::WrongPassword`,而不是既有的
`Crypto`。这不是措辞洁癖:两者的用户动作完全不同(重打一遍 vs 从备份恢复)。
钥匙串方案下仍报 `Crypto`——那条路上没有「密码」这个概念。

### D9 —— `Vault::open` 的签名不动,新增 `open_with`

`open(dir, key_source)` 保留原样,内部等价于 `open_with(dir, Unlock::Keyring(ks))`,
遇到主密码文件时返回 `StoreError::PasswordRequired`。理由是现有约 60 个调用点
(几乎全是测试)一处都不必改——改它们等于把本片的 diff 淹没在机械替换里,
真正的改动就没人看得见了。

### D10 —— 解锁弹窗在 app 侧,`store` 不问密码

`mullion-store` 零 UI 是架构不变量。所以:app 启动时先
`vault::probe_scheme(dir)` 探测,是主密码方案就先弹解锁框,拿到密码再
`open_with(dir, Unlock::Password(&pw))`。**store 永远不会主动索要密码。**

副作用是 `resumed()` 里「打开会话库之后」那一串动作(`refresh_appearance` /
`restore_tabs` / 自动弹会话管理器)必须能被推迟到解锁成功之后 —— 抽成
`finish_store_open()`,两条路径(直接打开 / 解锁后打开)共用同一份。

## 3. UI

### 3.1 启动解锁框(新)

一个 `egui::Window`,居中、不可关闭、无标题栏关闭按钮:

```
需要主密码
这台机器上的 secrets.enc 由主密码加密。

主密码 [••••••••]        ← 回车 = 解锁
        密码不对,再试一次        ← 红字,仅错过一次后出现

              [解锁]  [退出]
```

- 「退出」= 关窗口退出进程。不提供「跳过」:跳过意味着带着一个解不开的库继续跑,
  然后在用户双击会话时才炸。
- 弹窗开着时 `modal_open()` 为真(T8:键盘不能漏给终端)。此时还没有任何连接,
  但 CLI 直连路径可能已经起来了。

### 3.2 设置弹窗新增「安全」分节

`F84` 的设置弹窗(切片 F 建的)加一节,按 `docs/ui-form-guidelines.md`:

```
安全
  主密码    已设定 / 未设定
  新主密码  [        ]
  确认      [        ]
            两次输入不一致              ← 内联红字
            忘记主密码没有找回途径,已保存的密码与私钥将永久无法解开   ← 红字警示
            [设定主密码] / [修改主密码]     [取消主密码]
```

- 撤销**不要求**再输一次当前密码:能打开这个弹窗就说明库已经解开了,
  再问一遍是仪式感不是安全性。
- 空密码不算密码:两个框都空时按钮禁用(而不是设一个空密码)。

## 4. 不做

- **不做密码强度计**。强度计给的是虚假的精确度,而真正的风险(用同一个弱密码)
  它测不出来。
- **不做「记住主密码」**。记住 = 存在钥匙串 = 回到今天的方案,那用户就没有理由
  设主密码了。
- **不做密码找回 / 提示问题**。没有第二把钥匙是这个设计的**属性**,不是缺陷。
- **不加密 `sessions.toml` / `layout.toml` / `settings.toml`**。它们按 F70 的划分
  就是非敏感面,加密它们只会让「配置可被外部接管」(F48)更难。

## 5. 验收

无头能验的:派生纯函数、文件头编解码(含截断/垃圾输入)、方案探测、
设/改/撤三条路径的 round-trip、未设主密码时与今日的等价性、密码错的错误分类。

人工才能验的:解锁框的观感与回车行为、设置弹窗那一节的排版、
Windows 钥匙串在「设了主密码之后」不再被读(可用 Process Monitor,非必需)。
