# 会话列表：三档密度重排 + 选中态改节点色 + 状态点下线（F61/F62/F80）

> 2026-08-10。触及 `crates/mullion-app/src/ui/session_manager/list.rs`、
> `ui/badge.rs`、`ui/session_manager/fields.rs`、`ui/pane_title.rs`、
> `ui/session_manager/mod.rs`。零 store schema 改动。

## 背景

v0.1.27 的 F100 标注模式导出了当前左栏的实际布局，据此提出四条修改要求：

1. 三档密度的图标统一成 32×32；`Full` 档保持完整显示，`Compact` 只留图标 + 名称，
   `Icons` 只留图标（无图标的行隐藏）
2. 会话行的连接状态指示点隐藏
3. 选中行去掉左侧强调条，改用节点颜色做背景
4. 去掉可配的图标底色，图标底色跟节点颜色一致

四条都是**视觉与信息密度**的调整，不涉及数据模型。存储格式（`schema v5`）一个字节不动。

## 决策

### D1 三档密度重排

| 档 | 触发宽度 | 内容 | 行高 | 图标边长 |
|---|---|---|---|---|
| `Full` | ≥ 208 | 图标 + 名称 + `user@host` | 44 → **48** | 16 → **32** |
| `Compact` | 88 ~ 208 | 图标 + 名称（单行） | 40（不变） | 32（不变） |
| `Icons` | 56 ~ 88 | 只有图标，居中；**无图标的行整条隐藏** | 72 → **48** | 64 → **32** |

配套常量：

- `LIST_MIN_W`：88 → **56**
- `ICONS_BELOW`：132 → **88**
- `COMPACT_BELOW`：208（不变）
- `ICON_SLOT_X`（图标槽位中心距行左沿）：38 → **24**，即左边距 8px
- `text_x()` 随之从 54 → **48**
- `icon_px()` 三档一律返回 `ico::SMALL`（32）
- `Full` 档两行文字的基线随行高 44 → 48 各下移 2：名称 `top+7` → **`top+9`**，
  副标题 `top+25` → **`top+27`**（否则两行文字整体贴在行的上半部分）

**为什么 `LIST_MIN_W` 必须跟着降。** `density_for` 的唯一输入是宽度，而 `LIST_MIN_W`
是分隔条能拖到的下界。若 `ICONS_BELOW` 与 `LIST_MIN_W` 都取 88，`density_for(88)`
落在 `Compact`，`Icons` 档**永远不可达**——等于把第三档删了。88/56 错开之后，
「拖到最窄」才真的能收成一条 56px 宽的图标带，这正是这一档存在的理由。

**行高为什么是 48 而不是 44。** 32px 图标在 44 行高里上下各剩 6px，太挤；48 给到
各 8px，与左边距同数。`Compact` 维持 40 是因为它只有单行文字，32px 图标上下各 4px
在单行行内是可接受的（这一档本来就是「省地方」的档）。

### D2 `ico::LARGE`(64) 退出绘制路径

三档全用 32 之后，没有任何绘制点还在取 64 帧——`pane_title` 画的是 14px（走 32 帧）。

- **不动 `ui::ico::import` 的归一化**：它产出 32/64 两帧是**存储格式**的一部分，
  改它要迁移已有配置，收益为零。
- **编辑器的图标预览从「32px / 64px 两档并排」缩成只画 32px**。列表已经不再用 64，
  继续预览 64 是在骗人——而「小尺寸下还认不认得出」正是选图标时唯一要判断的事，
  预览的尺寸必须与列表真实取图的尺寸一致。

### D3 连接状态指示点整套下线

会话行不再画状态点；行左那块 12×12 的 hover 热区（`ui.interact(dot_rect, …)` 挂
`status_tooltip`）一并去掉——点没了还留浮层，等于在空白处埋一个看不见的提示。

**连带删除**（这套符号只在 `list.rs` 内部使用，别处零引用；不删则 `clippy -D warnings`
因 dead_code 直接把构建打红）：

- `Status`、`Marker` 两个枚举
- `status_of`、`marker_of`、`status_color`、`status_tooltip`、`paint_status`
- 三条守护测试：`status_of` 四态优先级、四态 marker 互不相同、四态 tooltip 各不相同
- `session_row` / `paint_row_body` 的 `status: Status` 参数
- `UiState` 里 `connecting` / `failed` 两个字段——**仅当 grep 确认再无其它消费者**。
  有别的消费者就只删列表这一侧，字段留着。

**承认代价：会话列表从此看不出哪台连上了。** 现存的其它状态出口只有 pane 标题条那颗点
（`PaneStatus::Live/Disconnected`）与状态栏，两者都只反映当前 pane，不是列表全局。

接受这个代价的理由：选中行将用节点色铺满，再叠一层状态色就是两套颜色语言在同一行里
打架；而「我正在用哪台」这个最常被查的信息，选中态本身已经答了。

### D4 行背景改用节点色

`session_row` 的背景取色，`selected` / `hovered` 两态都先看节点色：

| 态 | 有节点色 | 无节点色（回落现状） |
|---|---|---|
| 选中 | 节点色 **α = 0.28** 铺满，圆角 6 | `sunken_bg` |
| 悬停 | 节点色 **α = 0.14** | `panel_head` |
| 普通 | 透明 | 透明 |

删掉选中态那条左侧 3px `accent` 竖条。

**用低透明度而不是纯色铺满**：8 个预设色板里有浅色（黄），纯色铺满时 `fg` 白字会
掉到不可读；α 混合后底色始终由 `panel_bg` 主导，文字对比度不随用户选的颜色漂移。

**节点色仍走 `apply_to` 闸门**：只有勾了 `ColorTarget::ListItem` 的会话，选中/悬停态
才用节点色，否则走回落。F62 的规矩是「颜色画在哪由 `apply_to` 说了算」；不走闸门的话，
用户明确取消勾选「列表项」之后颜色照样从背景冒出来，那个勾选框就成了摆设。

**右边缘那条 3px 语义色竖条保留**：它是**未选中**行认色的唯一途径（选中行有背景色，
未选中行只有它）。左侧 accent 条腾空之后，左右不再打架。`TEXT_RIGHT_PAD` 不变。

### D5 图标底色改由调用方传入

```rust
pub fn paint_icon(p: &Painter, rect: Rect, icon: &IconSpec, bg: Option<Color32>)
```

`paint_icon` 不再自己读 `icon.bg`。三个调用点各传各的闸门色——图标画在哪个落点，
就用哪个落点的 `apply_to`：

| 调用点 | 传入的 `bg` |
|---|---|
| 会话列表行 `list.rs` | `should_paint(appearance, ColorTarget::ListItem)` |
| pane 标题条 `pane_title.rs` | `should_paint(appearance, ColorTarget::PaneTitle)` |
| 编辑器图标预览 `fields.rs` | 表单缓冲里当前选中的节点色 |

**闸门判断为什么不塞进 `paint_icon` 内部**：它拿不到 `target`，而同一张图在列表和
标题条上该不该有底色，答案可能不同（用户可以只勾其中一个落点）。

编辑器「图标」页删掉整行「底色 ☐ ■──」（勾选框 + 色盘），`DEFAULT_ICON_BG` 常量跟着删。

**`IconSpec.bg` 字段保留在 schema 里但不再读写**：旧配置里存的底色不丢、不崩、不需要
迁移；字段上补注释说明已停用。这也让将来若要恢复这个开关时数据还在。

## 不做什么

- 不改 `mullion-store` 的任何类型定义、`SCHEMA_VERSION` 或迁移链
- 不改 `ui::ico::import` 的归一化尺寸（仍产 32/64 两帧）
- 不给会话列表另找地方显示连接状态（D3 的代价已明确接受）
- 不动状态栏、Tab 条、分组头的任何绘制

## 测试

改动集中在绘制层，绝大多数只有人眼能判定。能自动验的是这些：

| 测什么 | 怎么测 | 自证会变红 |
|---|---|---|
| 三档切换单调、`Icons` 在最窄宽度可达 | 现有 `density_*` 测试改期望值；新增 `assert_eq!(density_for(LIST_MIN_W), Density::Icons)` | 把 `ICONS_BELOW` 改回 132 |
| `LIST_MIN_W < ICONS_BELOW` | `const assert` | 两数取相等 |
| 三档图标边长都是 32 | 断言 `icon_px` 三档相等且 `== ico::SMALL` | 任一档改回 16/64 |
| 行高容得下图标 | 三档断言 `row_h(d) >= icon_px(d)`；再按档断言上下留白：`Full`/`Icons` ≥ 8、`Compact` ≥ 4 | 只有 `>=` 那条时把 `Full` 行高改回 44 仍能过（44 > 32），所以留白断言是必需的第二道；`Compact` 阈值故意更松——它就是「省地方」的那一档 |
| `Icons` 档隐藏无图标的行 | 现有测试保留 | 删掉 `show()` 里的过滤 |
| 选中行不再画 accent 条 | 比对同一行 selected/非 selected 两次绘制的图元数差值 | 把竖条加回去 |
| 有节点色时选中背景 ≠ `sunken_bg` | 直接断言取色纯函数 `row_bg(selected, hovered, node_color)` 的返回值 | 忽略 `node_color` 直接返回 `sunken_bg` |
| 未勾 `ListItem` 的会话选中背景回落 | 同上，传 `None` | 绕过 `should_paint` 闸门 |
| `paint_icon` 用传入的 `bg` 而不是 `icon.bg` | 造一张 `icon.bg = Some(…)` 的图标、`bg = None` 调用，数图元 | 让 `paint_icon` 回头读 `icon.bg` |

**取色逻辑抽成纯函数 `row_bg(...) -> Color32`**（不收 `Ui`、不收 `Painter`），
否则「选中背景到底是什么色」只能靠数图元推断，测了也不知道测的是不是那一块。

## 人工验收清单（无头环境验不了）

1. 左栏拖到最窄（56）：是一条纯图标带，无图标的会话整条消失
2. 拖到 ~120：图标 + 名称单行，名称过长有省略号
3. 拖到默认 300：图标 32px、名称、`user@host` 两行，左边距 8px 看着不偏
4. 三档下都没有连接状态点，行左也没有隐形的 tooltip 热区
5. 选中一台配了颜色的会话：整行淡淡一层该颜色，文字清楚可读；换成浅色（黄）再看一次
6. 选中一台没配颜色的会话：跟改动前的灰底一致
7. 悬停未选中行：比选中态更淡的同色
8. 选中行左侧没有强调条；未选中的彩色行右边缘仍有 3px 竖条
9. 图标底色 = 节点色（同一块色），编辑器「图标」页已无「底色」那一行
10. 编辑器图标预览只剩 32px 一档，与列表里看到的一致
11. pane 标题条那个 14px 图标：勾了「pane 标题条」落点时有底色，没勾时没有
