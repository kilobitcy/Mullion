# 导入 `~/.ssh/config` 设计定案（F2）

> 切片 I。`spec.md` 里最后一个 P0。
> 目标：从 PowerShell + ssh 迁过来的用户，手上那份 config 能一次性变成会话库，
> 而不是照着文件一条条手抄。

## 范围

**做**：解析 `Host` / `HostName` / `Port` / `User` / `IdentityFile` / `ProxyJump`
六个关键字（spec F2 点名的那六个），预览勾选后批量落库，`ProxyJump` 回填成
本项目的跳板引用。

**不做**（超出就是另一个切片）：
- `Include` 展开（要递归 IO + 通配目录，spec 没要求）。遇到时**明说没展开**。
- `Match` 块（条件依赖 exec/user/localuser，语义远超 F2 的六个关键字）。
- 反向导出（写回 `~/.ssh/config`）。
- 读私钥正文（见 D5）。
- 覆盖已有同名会话（见 D6）。

---

## 决策

### D1 解析器放 `mullion-store`，新模块 `ssh_config.rs`

零 IO：吃 `&str` 吐结构，文件由调用方读。

理由：产物最终要变成 `SessionDraft`/`NetworkPrefs`，而只有 `store` 认识它们；
`mullion-ssh` 按架构不变量「不认识 pane/会话这些概念，只认字节流」，把会话
草稿塞进去是反方向依赖。放 store 还白拿一条好处 —— 解析器可纯单测，fixture
喂进去、结构比出来，正是 spec F2 的验收标准原文。

### D2 只吃那六个关键字，其余**忽略但计数**

未识别的关键字（`ServerAliveInterval`、`ForwardAgent`、`Compression`…）不报错、
不阻断，但要在预览里报「另有 N 条指令未导入」。

理由：静默丢弃会让用户以为整份配置都搬过来了，然后在某天发现某个 Host 的行为
跟 ssh 不一样 —— 而那时他已经不记得导入过什么。计数不需要认识这些关键字，
成本接近零。

`Include` 特殊：它不是「不认识」，而是「认识但没展开」，单独一条提示。

### D3 通配块按 ssh 的 **first-obtains** 语义合并，纯通配块不生成会话

ssh 的真实语义不是「后面的覆盖前面的」，而是**每个关键字取文件里第一次匹配到的
那个值**（`man ssh_config`：*For each parameter, the first obtained value will be
used*）。`Host *` 通常写在文件末尾当默认值，正好靠这条语义生效。

所以：
- 模式里含 `*` 或 `?` 的 `Host` 块**不生成会话**（`Host *` 不是一台机器），
  但参与匹配它的具体 Host 的取值。
- 一个 `Host` 行可以有多个别名（`Host a b c`）：每个非通配别名各生成一条会话。
- 否定模式（`Host !foo *`）**不支持**，遇到时整块跳过并计入「未导入」提示 ——
  半对的匹配比不匹配更危险。

### D4 `ProxyJump` 两阶段回填

本项目的跳板是 `JumpRef(SessionId)`（对另一条**会话**的引用），而 config 里写的是
主机别名。id 要等落库才有，所以：

1. 先按勾选建全部会话，记下 `别名 → SessionId`。
2. 再遍历一遍，把 `ProxyJump` 的别名翻成 id，`update` 回填 `network.jump`。

指向**本批之外**的别名（没勾选 / 不在文件里）→ 会话照常导入，但跳板留空，
预览里该行标黄写明「跳板 X 不在本次导入范围内」。**不凭空造一条跳板会话** ——
那是替用户往库里塞他没批准的配置。

`ProxyJump` 的 `user@host:port` 形式只取 host 段做匹配（user/port 属于跳板会话
自己的配置，不是引用点的事）。多跳（`a,b`）按顺序全部翻译。

### D5 `IdentityFile` **只记路径到备注，不读私钥正文**（用户 2026-08-13 拍板）

导入的公钥认证会话建成 `AuthKind::PublicKey { has_passphrase: false }`，私钥槽
留空，原始路径写进会话备注，预览里明写「私钥需在会话编辑器里手动导入」。

理由：v5 起私钥正文入库、不存路径。导入时批量读一堆私钥、遇加密的还要口令，
等于替用户做主往 `secrets.enc` 里搬一批私钥正文。路径写进备注则一条信息都不丢，
也不让会话跟某台机器上的某个文件绑死。

没有 `IdentityFile` 的 Host → `AuthKind::Password`（密码槽空，连接时提示）。

### D6 同名会话**不覆盖**，默认不勾选

与库里已有会话同名的行，预览里标「已存在」且默认不打勾。用户仍可手动勾上 ——
那会**新建一条同名会话**，不是覆盖。

理由：导入是加法。覆盖意味着一次点击可能抹掉用户手工调过的端口、代理、
登录后自动化 —— 而这些 config 文件里根本没有，合并出来一定是退化。

### D7 入口：菜单「会话 → 导入 ssh config…」→ 文件对话框 → 预览弹窗

不做「自动发现并提示导入」：开机弹窗问用户要不要导入是打扰，且 Windows 上
`%USERPROFILE%\.ssh\config` 存在与否跟用户想不想导入没关系。文件对话框的初始
目录指向它，省掉手动翻目录。

预览弹窗是一个 `egui::Window`，**必须计入 `modal_open()`**（T8 那条：弹窗开着时
键盘不能漏给终端）。

### D8 不建分组

导入几十条会话时「统统扔进一个新分组」看着整齐，但分组在本项目里持有**可继承
字段**（终端/外观/网络路径），凭空造一个空分组只是多一层继承链。用户想分组，
会话管理器里的「移动到分组」现成。

### D9 缺省值按 ssh 语义，缺 `User` 不阻断导入

- 缺 `HostName` → 用 Host 别名本身（ssh 就是这么干的）。
- 缺 `Port` → 22。
- 缺 `User` → **留空**，预览标黄「未指定用户名，导入后需补」。仍可导入 ——
  拦下来的话，一份没写 User（靠 ssh 默认取本地用户名）的 config 会一条都导不进来，
  而在 Windows 上那个默认值多半也是错的。

`Port` 不是数字 / 超出 u16 → 该行标红、**不可勾选**（造不出合法的会话）。

## 验收（人工，Windows）

1. 拿一份真实的 `~/.ssh/config` 导入，条目数与预览一致。
2. 带 `Host *` 默认块的 config：具体 Host 的 User/Port 取到通配块的值。
3. 带 `ProxyJump` 的两条一起勾选 → 导入后被跳板那条的「网络」页能看到跳板引用；
   只勾目标不勾跳板 → 目标导入成功且跳板为空、预览里有黄字。
4. 同名会话默认不勾，勾上后是新建一条而非覆盖。
5. 导入后真连一次（密码档）。
