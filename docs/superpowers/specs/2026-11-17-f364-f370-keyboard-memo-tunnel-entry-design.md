## F364 项目列表键盘高亮 + 打开即聚焦 + 项目管理器左栏导航

事实(grill 时核对):F343(v0.1.141)已给启动页、切换项目弹窗(`ui/project_pick.rs`,
即 pane 标题条「把这块分屏切到另一个项目」按钮)接了 ↑↓/Enter(`ui/project_nav.rs`)。
用户实报「高亮不明显」,根因:选中态走 `session_manager::list::row_bg` 的 `sunken_bg`,
与面板底、悬停的 `panel_head` 都太近。另外两处搜索框**打开时不自动聚焦**(只有测试里
`request_focus`),不先点一下框,键盘导航整条不生效。

决策:
1. **高亮 = accent 薄色底 + 左缘 3px accent 竖条**,与焦点 pane 标题条同一语言
   (`accent.gamma_multiply`)。三处项目列表(启动页 / 切换项目弹窗 / 项目管理器左栏)
   共用同一画法;项目管理器左栏「当前编辑的项目」也用它。悬停仍是灰,与键盘高亮分得开。
   **复用 `files_panel.rs` F150 的现成画法**(accent 半透明铺满 + 行首实色条),不再造一份。
   项目行调 `row_bg(.., None, t)`,不走节点色分支;**不改 `row_bg` 本身**(会话管理器列表
   共用,`list.rs` 有选中 = `sunken_bg` 的断言),在 `project_row` 内单独画。亮灯底
   `lit_tint`(`t.ok` 薄绿)垫在下面时与 accent 叠加的观感需人工确认(F266 曾为
   「亮灯不抢选中态」调过)。
2. **打开即聚焦**:切换项目弹窗打开那一帧聚焦搜索框;启动页在**进入启动页那一帧**
   聚焦一次。只聚焦一次,之后不反复抢焦点(用户点别处就让)。
   **不搭 `HistorySync::Reload`**(复核二):它在启动第 1 帧、主密码解锁框还开着时就触发,
   且 launcher 画在解锁框之后、同帧后到的 `request_focus` 胜出 → **主密码明文打进搜索框**;
   而正常解锁路径 `finish_store_open` 直接写 `launcher_history`,Reload 反而不在该聚焦时
   触发。判据改为与 `unlock.rs` 同一手法:**launcher 态 且 `ui.unlock.is_none()` 且
   `!modal_open()` 且这一帧无人持焦点** → 聚焦一次(用一个「本次进入已聚焦过」标记,
   离开 launcher 时复位)。守护测试须覆盖「解锁框开着时不抢焦点」。
3. **项目管理器左栏**:接同一份 `project_nav`。
   - ↑↓ 仅在左栏搜索框有焦点时生效;右栏跟着切(同点击)。
   - **右栏有未保存改动时 ↑↓ 不切**,原地不动,并让既有「有未保存的改动,先保存再打开。」
     提示更醒目 —— 连按 ↓ 冲过头静默丢草稿的代价不对称(鼠标点击的静默替换是既有
     行为,不在本条改)。F236「+ 添加项目」刚建的草稿天然脏,此时 ↑↓ 不动 —— 符合预期。
     `dirty` 现在 `form_column` 里算、而左栏先画,↑↓ 在左栏扫 → 抽一个纯函数两处共用,
     不复制判据。
   - **Enter = 点「打开」**:同一条 `project_open_request`,确认框/踢下线链路照旧;
     不可打开(无节点 / 有脏改动)时 Enter 无动作,与按钮置灰一致。打开后管理器开合
     沿用按钮现行为。「已归档」档下 Enter 照样能开(与按钮一致,`openable` 不看归档)。
   - 同步改 `project_nav.rs` 模块注释与 F343 spec 行里「项目管理器不动」。

## F365 Alt+拖选复制时「你/您」→「我」

在 F335(Alt+拖选复制为单行)的结果上,把每个「你」「您」替换成「我」,其余一字不改。
- **直接改 Alt+拖选**,不另起组合键、不加开关(用户拍板:Alt 复制从不用于别的内容)。
- 逐字替换:「你们」自然成「我们」;不做反向「我→你」,不做语义判断。
- 多行经 Alt 拼成一行后同样替换,规则不分单行/多行。
- 场景:Claude Code 问「需要你拍板的…」,复制回去当自己的答复。
- **替换放 app 层**(`copy_selection_one_line` 一侧),不进 `mullion-term`:
  `join_as_one_line` 是终端语义、有 fixture 守着,人称替换是产品策略。
- **发生了替换就飘 `Kind::Warn` toast「已将 N 处你/您改为我」**(现仅在「合并了多行」时飘
  `Kind::Ok`)。复核二指出 F335 本身的动机是复制折行命令行(fixture 即 `git commit -m …`),
  命令/commit 信息里的「你」、「迷你」等会被改字;用户 2026-11-17 复议后维持「一律替换」,
  以醒目 toast 兜底。

## F366 下载覆盖失败弹窗告警

方向:**远端(如 Ubuntu)→ 本机 Windows**。覆盖走原地写(D19),Windows 上目标被
Excel/WPS 等独占打开时在**打开**即被拒(os error 32),原文件不被截断。现状只在传输
面板一行红字(原始 `io::Error` 文本),面板收起/F308 自动清后完全看不见。

决策:
- 范围**只管用户明确选了「覆盖」的那批**;其它下载失败维持面板红字。
- **模态告警框**「覆盖失败」:列失败文件(批量合并一框,超出 N 个写「等另外 k 个」,
  同批量冲突框写法),每个附**翻译后的原因**:
  - os error 32 / 33 → 「文件正被其他程序占用(例如 Excel),关掉它后重试」
  - os error 5 → 「没有写入权限(文件可能是只读的)」
  - 其它 → 原文
- 按钮「**重试**」(只重跑失败那几个,仍按覆盖)/「关闭」。

实现约束(复核吸收):
- **错误码来源**:worker 已把 `io::Error` 格式化成 `String`(`app.rs` 覆盖路径
  `"写不了本地文件:{e}"`,队列 `JobState::Failed(String)`)。**不改 worker 签名**,在
  `files/fail.rs` 解析 std 固定的 `(os error N)` 后缀;一条纯函数单测钉住该格式假设。
- Windows 上 `io::Error` 的描述来自 `FormatMessageW`,zh-CN 系统给中文;「其它 → 原文」
  即本地化文本。
- **重试**:队列无 retry API,`Failed` 是终态。重试 = 新 push 带 `Conflict::Overwrite`
  预设的 job(同 `paste_files.rs` 手法),**并把旧 `Failed` 条目摘掉** —— 否则 F308
  「有 Failed 永不自动收」使传输栏永不收起。
  - `TransferDone` 里凡 finished 即 `specs.remove`,弹窗时路径已丢:**把失败 job 的
    `TransferSpec` 拷进告警结构体**(不改 specs 回收纪律)。
  - `Queue` 只有 `clear_finished` 全清,**新增 `remove(id)`**(单条、仅限终态)。
- 告警框**不占 `files_dialog` 单槽**(那条槽「已有框开着就等」,批量下载时会与后续冲突框
  互相排队):独立一个槽,登记 `Modal`。
- 已知边界:`File::create` 被拒时原文件完好;`write_all`/`flush` 中途失败时目标**已被原地
  截断**(D19),两者文案相同。写进人工验收清单,不在本条区分。

## F367 Ctrl+Shift+M 项目备忘浮层

事实:pane→项目归属已可算(按 tmux 会话名,`project.rs` 有守护);F294 可配热键框架
已有 7 个动作。

决策:
- 新增 `hotkeys::Action`,默认 **Ctrl+Shift+M**(已核对无占用),设置页可改键。
- 浮层**锚定焦点 pane**(同 `project_pick` 定位),标题「项目名 · 备忘」。
  - 上半部:「新增备忘」输入框,**打开即聚焦,回车即加一条并立即落盘**;下面倒序列出
    已有备忘,每条可删。
  - 下半部:`note`(长期说明)**默认折叠**,点开可编辑;保存语义与项目管理器一致。
  - Esc / 点浮层外关闭。
- **必须登记进 `app.rs::modal_open`**(T8:否则打的字同时漏给远端 shell)。
- pane 不属于任何项目 → 不弹空浮层,toast「这块分屏不属于任何项目」;不做顺手建项目。
  **区分「还没上报 tmux 名」与「无归属」**(`project_of` 返回 `None` 两义):前者 toast
  「这块分屏还在连接,稍后再试」。焦点不在任何 pane(文件面板 / SFTP 标签)→ 无动作。
  从项目打开的 pane 在上报 tmux 名之前也会得到「还在连接」(运行时 pane 无项目 id 字段),
  可接受,写进验收清单。
- 「回车即加一条」**必须复用 `project_nav` 的同帧 `ImeEvent::Commit` 闸**(F314/F316
  两次翻车),是要求不是待验项。该闸现内嵌在 `project_nav::scan` 里与 ↑↓ 绑死,**先抽成
  独立函数**再两处调用,不复制粘贴。
- 落盘走 `update_project`,它先 `validate`:项目当前不合法(如节点会话已删)时加备忘会
  失败 → 浮层内联红字报错,不静默丢。
- 浮层是 Modal,`bound_hotkey_event` 整组让位,所以再按 Ctrl+Shift+M **不会**关浮层,只有
  Esc / 点外。浮层同时登记 `Modal::ALL` 与 `dismiss.rs` 候选表。
- `note` 有未保存改动时点外**不关**,沿用 `ui/dismiss.rs` 的脏改动约定;Esc 同理先问。
- 加第 8 个 `hotkeys::Action`:`ALL: [Action; 7]` 与 `hotkeys.rs`/`settings.rs`/
  `shortcuts.rs` 多处写死的「7 条」一并改。
- 已知风险(不在本条修):落盘走 `update_project` 整份替换,多开时另一实例项目管理器
  Save 会盖掉这边新加的备忘 —— 既有「整份覆盖族」(F247/F248),高频写入使暴露概率上升。
- 标题条不加按钮(已有三个),入口 = 热键 + 快捷键一览表。

## F368 隧道自动启动(推翻 §4.12 旧边界)

旧边界(spec §4.12):不做 autostart,理由「每条隧道启动都是一次完整建链,可能要
TOFU/密码/口令,开机并发拨 N 条等于糊一屏模态框」。**2026-11-17 推翻,改为
「自动启动不做交互」**:旧理由担心的是交互框,不是自动启动本身。

决策:
- 激活既有 `TunnelRecord.autostart`(已落盘,schema 不动),编辑器出复选框「自动启动」。
- 时机:**库打开成功之后**(`finish_store_open` 且 `store.is_some()`;该函数在打开失败
  路径也会被调,先判空)。设了主密码即「解锁之后」。**CLI 直连路径在该函数里提前
  `return`,挂钩点须在它之前**(或 CLI 启动明确不拉,二选一,实现时定并写测试)。
  F148 起启动不自动恢复现场,故无须与 F153 串行拨号排序。
- **只走无需交互的路**:
  - `start_tunnel` 现状首连固定 `PromptingPolicy`(会弹 TOFU)。**加首连策略参数**,
    自动路径首连也用 `TrustedOnlyPolicy`(类型上不可能弹窗);浮层/管理器手动启动仍
    `PromptingPolicy`。
  - 主机密钥要握手中途才知道,无法拨前判断:实际是「拨一次 → `HostKeyUnknown`」。
    `MissingSecret` 在 `ssh_config_for` 阶段即知,自动路径**不走 `set_error`**(否则
    N 条缺密码连弹 N 次顶栏红字)。
  - **机制(复核二修正)**:`start_tunnel` 同步 `insert` 并发布 `Connecting`,失败要等异步
    状态,「不登记」做不到;`TunnelState::Failed(String)` 又禁止 UI 二次分类。改为:
    记一个**本次自动拉起的 id 集合**;自动路径下收到 `Failed`(不论原因)即
    `self.tunnels.stop(id)` 并**再 `publish_tunnel_state`**(否则别的窗口一直显示「在另一个
    窗口连接中…」),且**不发 F115 的跃迁 toast**(否则 N 条就是 N 个 toast)。不分类失败
    原因、不改 `TunnelState`/`RemoteTunnelState`、不做字符串匹配。
  - 结果:那条在 F369 浮层里回到可点的「启动」;状态栏只加一句「N 条未自动启动」
    (= 集合里没到 Running 的条数)。
  - 自动路径下 bind 失败、`MissingSecret` 同样不走 `set_error`,一律计入「未自动启动」。
- **逐条串行**:`start_tunnel` 同步 spawn 即返回,状态走 `UserEvent::TunnelState`。
  **每条等到首次状态上报即放行下一条**(不等 `Running`,免得一条 F114 退避卡住全队);
  照搬 F153/F162 串行拨号队列「闸 + 两条路径都复位」的纪律。
- **多开定主**:**在真正要拉的那一刻**(上一条之后)对 `<config>/tunnel-autostart.lock`
  调 `std::fs::File::try_lock`(std 1.89 起自带,返回 `Result<(), TryLockError>`,不加
  依赖)。抢到的实例负责拉起并持锁到进程退出,没抢到的什么都不做;退出/崩溃由 OS 释放。
  **主实例退出后不自动接管**(其它窗口按钮恢复可点,手动启动)。锁放解锁之后,避免
  「A 停在解锁框、B 抢不到锁 → 谁都不拉」。迁移包是白名单 `TOP_LEVEL_FILES`,锁文件
  不会被卷入(已核)。
  理由:F338 的在场文件是事后可见、不是锁,两个 exe 几乎同时启动时都读不到对方,
  后到的 bind 失败 → 红色假告警 + 白建一条 SSH 连接。
- 拉起失败只在状态栏标红,不弹窗,不自动反复重试(F114 的运行中重连照旧)。

## F369 状态栏隧道指示器常驻可点 + 启停浮层

现状:入口为 菜单「会话」→ 会话管理器 → 隧道页 → 选一条 → 启动/停止;指示器只在有
隧道在跑时出现且不可点。

决策:
- 配置了 ≥1 条隧道就常驻(`隧道 0/3` 灰),**可点**。
- 点开浮层,每条一行:`名字 · 本地 3306 → db:3306 · 状态 · [启动/停止]`;状态与按钮
  复用 `tunnel_list::button_spec` / `other_label`(「在另一个窗口运行」等原因照样置灰
  说明)。autostart 只显示小标记,不在浮层改。
- 每行末「编辑」跳会话管理器隧道页并**选中该条**(改端口用);底部「管理隧道…」。
- 不做顶层「隧道」菜单:菜单项不好放状态色,且把状态与操作拆两处。
- **推翻 F115「没有在跑的隧道时不占格」**(`chrome.rs` 守护):守护测试改名重写为新语义,
  不是删断言。
- **计数含别的实例**:`tunnels::indicator` 现只数本实例;分子须把 F338 `others` 里的
  `Running` 算进去(或分开标注),否则多开时 B 显示「0/3」与列表「在另一个窗口运行中」
  自相矛盾。
- **浮层登记为 `Modal`**(`Modal::ALL` 与 `dismiss.rs` 候选表两张都加):否则 Esc 被终端
  截走(先判后喂,T8 同族;F322 记录)。
- 浮层「启动」走手动路径(`PromptingPolicy`,人在屏幕前,可弹 TOFU)。
- `button_spec(dangling, live, elsewhere)` 需调用方先算三项判据(含 `other_for`),把这套
  判据从 `tunnel_list` 抽成共用函数,浮层与列表同源。
- 浮层开着时,`start_tunnel` 的报错(`set_error` 顶栏)用户看不见 → 该条行内显示最近一次
  错误。

## F370 本地侦听端口查重

Windows 默认允许 `0.0.0.0:P` 与 `127.0.0.1:P` 同时 bind 成功,流量被更具体的地址抢走,
**静默错路**。

决策(复核后改,原定硬拦截会打掉「测试库/生产库都映本地 3306、只开一条」的互斥备选
用法,且克隆后两条同端口 → 连改备注都存不了):
- 保存时另一条隧道已占同一本地侦听端口 → **黄字警告,照存**。
- **仅当两条都勾了「自动启动」时拦截** —— 开机静默错路正是 F368 引入的新风险,精确覆盖。
- 查重范围:本地侦听的 `Local`(含 `expose=true`)与 `Dynamic`(恒回环)都算;`-R` 侦听
  在远端,不在此列;排除自身 `editing_id`。
- **编辑时实时校验**(表单内联,保存按钮旁),不是保存后一闪:现 `build_tunnel_draft(buf)`
  拿不到其它隧道,查重做成另一个纯函数,入参带全部隧道。
- **克隆一律 `autostart = false`**(`vault.rs::clone_tunnel` 一行):否则克隆一条 autostart
  隧道 = 两条 autostart 同端口,整个拦截被绕过,恰好制造 F368 要防的开机错路。
